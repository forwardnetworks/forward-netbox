# Release 3.0.10

## Goal

Ship the support-bundle completeness tranche that follows 3.0.9: a customer reading figures off a page can find each one in their bundle under the page's own label, with its split and the devices behind it, and the bundle explains the devices without a primary IP that the sync does not manage and every shared-address owner. It also accepts netbox-routing 0.5.1 and closes a name leak in the exported audit button jobs.

## Constraints

- No customer names, network IDs, snapshot IDs, hostnames or addresses in the repo, plans, tests or docs. Tests use synthetic names.
- No shipped NQE query changes, so there is nothing to republish. No migration.
- The bundle stays name-free: counts, slugs and NetBox primary keys only. Tag names and audit example names stay out.
- netbox-routing 0.5.0 stays accepted alongside the new 0.5.1 pin.
- Explanatory text reports what the management-address step recorded; a device with no record gets advice naming every cause that leaves none.

## Touched Surfaces

- Support bundle: `forward_netbox/views.py`, `utilities/bundle_ui_figures.py`, `utilities/bundle_label_index.py` (label and card index), `utilities/primary_ip_reasons.py`, `utilities/explained_findings.py`, `utilities/export_redaction.py`.
- Audit button jobs in the operator-action export now reduce stored payloads to counts (a 3.0.9 name leak).
- netbox-routing 0.5.1: `validated_runtime.py`, `plugin_integrations/registry.py`, constraints files, `poetry.lock`.
- Tests: `test_log_export`, `test_bundle_ui_figures`, `test_bundle_label_index`, `test_explained_findings`, `test_optional_plugin_versions`, `test_plugin_integrations`.
- Release surfaces written by `scripts/release.py` (version strings, README tables, CHANGELOG) and the digest fix from PR 594 on the tag stage.

## Approach

1. PRs 594 to 600 merged to `main`; the full Django suite passed on the final tree (4161 tests, 33 skipped).
2. Run `scripts/release.py 3.0.10` through the usual lineage: cut, authorize, evidence, tag, post-release bridge, anchor.
3. After the tag nothing needs republishing. A customer upgrades and re-syncs; the next bundle carries the index, the outside-sync accounting and the shared-owner list.

## Validation

- `invoke ci` on the release tree via `scripts/release.py`, including the artifact and upgrade legs.
- The full Django suite on `main` at the last merge: 4161 tests OK. Scripts tests: 461 OK.
- `pre-commit run --all-files` and `invoke harness-check`.
- Not verified: the 3.0.10 tag push is the first real test of the gated-tree digest fix (PR 594); whether netbox-branching keeps device primary keys on merge for outcomes keyed by branch pk.

## Rollback

Revert the release. The new bundle sections are additive and an older plugin ignores them.
