# Release 2.7.5

## Goal

Get the ownership fixes to the customer. 2.7.4 shipped without them - the scope
tranche merged after the tag - so the version they installed contains none of
the work aimed at what they are actually reporting.

## Contract

- The four version surfaces move in ONE commit. Splitting them reverts the fast
  baseline from minutes to hours with nothing reported.
- The release commit carries its own release-authorization section, whose
  evidence base commit equals the parent of the commit that gets tagged. Never
  write that heading's text earlier in the plan: the checker splits on its first
  occurrence.
- The tag is created locally, provenance verified, and only then pushed.
- The first first-parent commit after the tag is documentation-only.
- No `.devN` is opened on `main` afterwards.

## Constraints

- Gates run locally now; there is no CI to catch anything. Run the FULL plugin
  suite, not the suites that look adjacent - that is exactly how a red test
  reached `main` after #153.
- Disarm auto-merge before touching branch protections. An armed auto-merge
  merged a release branch as last pushed rather than as it stood, and cost a
  correction PR on 2.7.4.
- The prior-release tag is hardcoded in five coupled places.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`

## Approach

Everything in this release is already on `main` and already ran the full plugin
suite: #153 (the scope reconciliation tranche) and #157 (the ownership
provenance and reserved-tag fixes). This change is the version bump and the
release notes.

## Validation

`invoke ci` and `invoke artifact-test` on the pinned environment, then the tag,
then `verify_release_provenance.py` against the local tag before pushing it.

## Rollback

Before the tag is pushed, revert the branch. After it is pushed the tag is
immutable and a defect costs a version number - which is what 2.7.3 cost.

## Decision Log

- **Cut immediately rather than batching.** The customer is sitting in a state
  with no operator remedy: ownership never completes, so convergence is blocked
  and every drift figure reads "Not measured". Every day on 2.7.4 is another day
  of that.
- **The reserved-tag fix is the likeliest cause, not a confirmed one.** Their
  tag table was never inspected - the diagnostic buffered out twice and further
  probing was not warranted. The catalogue fix ships alongside it, so if the
  conflict survives, the next run names which of the nine it is instead of
  `unrecognized-ownership-conflict`. That is the durable part.

## Open

- The 40 out-of-scope devices are not addressed here and may not be a defect:
  membership is decided by absence from the Forward result under the configured
  include tags, so whether those devices should carry those tags is a
  Forward-side question. The prune guard stops a collapsed scope deleting them.
