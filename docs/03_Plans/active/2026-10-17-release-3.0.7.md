# Release 3.0.7

## Goal

Ship change control and validation as an operational feature (PR 563): a change is authored, scoped to a Forward workspace, reviewed, verified and closed from the UI and the REST API; validation policies gate approval and close on a current run that answered every rule; notifications, event types, GraphQL and a branch-page panel. Also ship the support-bundle diagnostics that name why subinterface rows are skipped, and the fix that makes a `Mgmt_` tag that matches several interfaces use the one that carries the address.

## Constraints

- No customer names, network IDs, snapshot IDs, hostnames or addresses in the repo, plans, tests or docs. Tests use synthetic names and documentation addresses.
- No shipped query changes (`forward_netbox/queries/` is untouched), so there is nothing to republish to a Forward organisation.
- Migration `0066` adds the validation tables and depends only on `dcim.0001_initial` and `extras.0001_initial`, so it resolves on the oldest supported NetBox. Existing installs run `migrate`.
- Predict and Forward AI are only detected, never required: where Forward refuses them (a missing licence, a switched-off setting) the page says so and everything else works.
- The release notes say to run `migrate` after upgrading.

## Touched Surfaces

- `forward_netbox/change_control/`, `api/`, `graphql/`, `models.py`, `forms.py`, `views.py`, `urls.py`, `jobs.py`, `migrations/0066_change_validation.py`, templates, tables, navigation.
- `forward_netbox/utilities/primary_ip.py`, `interface_naming.py`, and the bundle sections in `views.py`.
- `scripts/validate_installed_routes.py`, `scripts/check_harness.py`, `docs/01_User_Guide/change-control.md`, `operations.md`.
- Release surfaces per `scripts/release.py`.

## Approach

1. PR 563 merged to `main` after the full pre-push gate passed (3,848 tests, the UI, docs, package and artifact upgrade tests).
2. Run `scripts/release.py 3.0.7` through the usual lineage: cut, authorize, evidence, tag, post-release bridge, anchor.
3. After the tag, ask the reporting customer for a fresh support bundle: it now carries the per-reason subinterface skip counts and the `change_control` section.

## Validation

- PR 563: five independent code-reviewer audits across the slices (each found real defects, fixed with tests), the full suite on the final tree, the whole pre-push CI gate, and the artifact upgrade test from 3.0.5 on NetBox 4.7.0 to this tree on 4.7.2.
- Read-only checks against a production organisation: the estate's device names in one query, and Predict and Forward AI refused with Forward's own reasons.
- `invoke ci` on the release tree via `scripts/release.py`.
- Not verified: a plugin-created workspace copying Forward's intent checks (needs a throwaway write to Forward), Predict proposal authoring, and Forward AI, none of which the reference organisation allows.

## Rollback

Revert the release. Migration `0066` only adds tables, and reverting leaves them in place; no sync behaviour depends on them. The `Mgmt_` resolver change restores the previous first-match behaviour on revert.

## Decision Log

- Released as 3.0.7 rather than 3.1.0 at the maintainer's call, although it adds a migration and a feature.
- Validation is judged per policy on a run that ran that policy's rules, and an unanswered rule blocks a gate whatever the score.
- Notifications and event rules are delivered after the change commits, so a failure in either never undoes the change.
- The release-only sensitive-pattern feed is a GitHub secret and cannot be read locally, so the cut runs with the parity bypass and relies on the local scanner, a scan of the full branch diff, and synthetic fixtures; the release workflow runs the real feed at tag time.
