# Release 2.9.8

## Goal

Cut `2.9.8` on the `maint/2.9.x` lane to fix a sync that fails on every run
after upgrading to 2.9.7, and to ship the diagnostics that would have found it
without live probing. Bump every version surface together and record the
release note for the four commits merged to `maint/2.9.x` since `v2.9.7`.

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `2.9.8` together, or `check_harness.py`
  refuses the release.
- The tested runtime is unchanged at NetBox `4.6.10`; the new table rows say so.
- No code change in this commit: both functional changes already landed as
  their own reviewed, `invoke ci`-green PRs.
- No customer names, identifiers, or scan-matching hostnames in this plan, the
  changelog entry, or the release commit message.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`,
  `CHANGELOG.md`
- this plan

## Approach

`scripts/release.py 2.9.8 --write` bumps every version surface and the
fast-baseline pin in the same commit and regenerates `CHANGELOG.md` from the
README compatibility table. The four commits it covers (oldest to newest):

1. **2.9.7 post-release bridge + provenance anchor** (`bf2e2ec`, `06647ed`) -
   documentation and tooling only.
2. **Support bundle diagnosability** (`219402a`, #455) - a bulk constraint
   failure names the conflicting NetBox row by primary key; the live
   query-drift check reports a published query whose `@query` parameter list
   no longer matches the bundled one (the cause of a 2.9.7 upgrade outage for
   org-backed maps); the dependency preview carries why each model failed.
   Exports now go through one redaction choke point, which also closes a leak
   of include-tag parameter values into support bundles. Adds migration
   `0057`. Plan: `2026-09-22-support-bundle-diagnosability.md`.
3. **Match devices case-insensitively** (`91e1e31`, #456) - NetBox's
   `dcim_device_unique_name_site` is `Lower("name"), "site"`, but both device
   apply paths matched existing devices by exact name, so a device whose name
   differed from NetBox's only in case was classified as new and the create
   was refused - failing the whole sync on the bulk path. Plan:
   `2026-09-22-device-name-case-identity.md`.

The release note also corrects 2.9.7's "No migration; upgrade and re-run the
sync" for org-backed deployments: 2.9.7 changed the parameter signature of the
interface and IPv4 address queries, so those deployments must run Publish
Bundled Queries.

## Validation

- `invoke ci` passed on each PR before merge (#455: 2938 tests; #456, rebased
  on #455: 2942 tests, 9 skipped, with scripts tests and the artifact-upgrade
  leg).
- #456's regression test, run against the unfixed code, reproduces the
  reported failure verbatim (`duplicate key value violates unique constraint
  "dcim_device_unique_name_site"`).
- `scripts/release.py 2.9.8 --write` verify step: version-surface
  consistency, UI harness dependencies, advisories, Dependabot alerts,
  `poetry.lock` parity, `check_harness.py`, full `invoke ci` and
  `invoke artifact-test`.
- The sensitive-pattern parity check runs UNVERIFIED in this checkout
  (`FORWARD_SENSITIVE_PATTERNS` is a CI-only secret); the release gate applies
  the superset feed and can still refuse the tag.

## Rollback

This commit is a version bump and changelog entry only. Reverting it restores
the previous version surfaces; the functional PRs need their own reverts.
Migration `0057` only adds two nullable/defaulted fields to `ForwardNQEMap`.

## Decision Log

- **Released immediately rather than batched.** A customer's sync fails on
  every run until this ships; the diagnostics PR ships with it because it
  already merged and it is what makes any remaining failure on that
  deployment self-describing.
