# Advance the release provenance anchor to 2.9.4

## Goal

Move the provenance anchor onto the shipped 2.9.4 release and promote it to
current in the compatibility tables, as one commit.

## Constraints

- The bridge must be the first commit after the tag on the first-parent lineage
  and documentation-only. `b35b5334b8d6` was checked for both by
  `scripts/release.py --anchor` before this file was written.
- The table promotion belongs here, not on the release branch: the harness
  requires the anchor to name the release the table calls current, so the two
  can only move together.

## Touched Surfaces

- `scripts/verify_release_provenance.py`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`
- this plan

## Approach

Anchor to `v2.9.4` / bridge `b35b5334b8d62ea672837200dc3324c9e986c509`; promote 2.9.4 to current and demote
the previous release to superseded.

## Validation

`check_harness.py --base <lane>` passes with the anchor advanced.

## Rollback

Revert; the harness fails again, which blocks the next release rather than
permitting an unverified one - the safe direction.

## Decision Log

- **Generated by `scripts/release.py --anchor`.** The anchor and the promotion
  were hand-edited for every release through 2.9.1, and skipping either was
  silent at the time and expensive later.

- **The provenance fixture now derives its tag from the anchor.** Advancing the
  anchor to `v2.9.3` left `test_verify_release_provenance.py` verifying that
  same tag, and its two entries for `refs/tags/v2.9.3` collapsed into one dict
  key - so every test resolved the tag under verification to the PRIOR release,
  thirteen failed on a missing `merge-base` response, and this lane's
  `invoke ci` stayed red until the next release tried to use it. 2.9.4 fixed
  that by naming the next tag explicitly, and this anchor would have recreated
  the collision one release later: `PRIOR_RELEASE_TAG` becomes `v2.9.4`, which
  was exactly `TAG_UNDER_TEST`. The guard added in 2.9.4 caught it here, in one
  assertion rather than thirteen errors.

  The fixture derives the next patch version from `PRIOR_RELEASE_TAG` instead,
  so the anchor advance carries it automatically. This is the manual step the
  anchor tooling never knew to perform, and a step no one remembers is a step
  that fails.
