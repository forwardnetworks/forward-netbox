# Move the tested runtime to NetBox 4.7.2 and netbox-branching 1.2.1

## Goal

Bump the declared tested-on runtime on the 3.x lane from NetBox `4.7.1` to
`4.7.2` and netbox-branching `1.2.0` to `1.2.1`. Both are patch releases of
the series this plugin already targets. `4.7.2` (2026-09-29) fixes plaintext
API tokens being recorded in background-job results on `4.7.0`/`4.7.1`;
branching `1.2.1` (2026-09-09) recovers branches left in a transitional status
when a worker dies and makes `ObjectChange.undo()` call `save()` when
restoring non-MPTT objects.

## Constraints

- **`min_version` stays `4.7.0`** and the branching requirement stays
  `>=1.2.0,<1.3.0`: those are floors and series bounds, not the tested-on
  pin, and `1.2.1` satisfies them.
- **`scripts/tested_runtime.py` is the single declaration.** The harness names
  every other site that disagrees.
- No plugin behavior change; this is a pin move only. The gate decides whether
  the undo-path change in branching `1.2.1` affects our merge or revert code.

## Touched Surfaces

- `scripts/tested_runtime.py` (`TESTED_NETBOX_VERSION`)
- `development/Dockerfile`, `development/docker-compose.yml`
- `tasks.py` (default `NETBOX_VER` and the two artifact-validation guards)
- `scripts/validate_installed_artifact.py`, `scripts/validate_sbom.py`
  (NetBox and branching pins), `scripts/check_release_authorization.py`
  (literal pins and the evidence-text regex) and its test
- `scripts/release.py` (help-text example only) and the script-test fixtures
  that hardcode the tested versions (`scripts/tests/test_release.py`,
  `test_release_authorization.py`, `test_tasks.py`, `test_validate_sbom.py`).
  `check_harness.py` does not sweep these; the first push failed 14 script
  tests on them, and `check_release_authorization.py` also pins
  `Branching 1.2.x` as an evidence-text regex.
- `constraints.txt`, `poetry.lock` (`netboxlabs-netbox-branching`),
  `forward_netbox/tests/test_optional_plugin_versions.py`

## Approach

Edit `TESTED_NETBOX_VERSION`, run `python scripts/check_harness.py` and fix
every site it names. `poetry lock` alone does not move an already-satisfied
pin, so the branching entry is moved with
`poetry update netboxlabs-netbox-branching --lock`.

## Validation

- `python scripts/check_harness.py` passes.
- Full `invoke ci` pre-push gate on NetBox `v4.7.2` with branching `1.2.1`,
  including the artifact-upgrade-test leg.

## Rollback

Revert this branch. No migration, no persisted state, no runtime-gate change.

## Decision Log

- **Patch bump, not a series move.** `VALIDATED_NETBOX_SERIES` and
  `min_version` need no change.
- **Shipped as its own change, then released as 3.0.3**, so a failure in the
  bump cannot hold back a fix release.
- The `undo()` behavior change in branching `1.2.1` is treated as a risk to
  test, not assumed safe.
