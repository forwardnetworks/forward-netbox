# Release 3.0.18

## Goal

Ship the site mapping rules table: the rules on the Forward source are edited as a table
(a row per rule with kind, Forward tag or location, and NetBox site pickers, existing
NetBox sites suggested) instead of one line per rule. The textarea stays the posted field.

## Constraints

- No customer names, network ids, snapshot ids or hostnames in the repo.
- Plugin only: no migration, and the bundled queries do not change, so no republish.
- Storage, validation and the text format are unchanged; a source with rules saved by
  3.0.17 loads as rows and saves back identically.
- `development/constraints-upgrade-from.txt` keeps `forward-sdk==0.1.36`, 3.0.17's pin;
  this release does not move the SDK.
- The release-time sensitive-pattern feed is a CI secret and cannot be read locally, so
  the cut runs with the unverified-parity flag; the publish workflow can still refuse.

## Touched Surfaces

- `forward_netbox/widgets.py`, `tests/test_site_rules_source.py`,
  `scripts/forward_ui_harness.mjs`, `docs/02_Reference/site-mapping-rules.md`.
  Plan: `2026-11-20-site-rules-table.md`.

## Approach

The tranche (PR #646) went through three code-reviewer audits; the fixes are in its
commits. Then `scripts/release.py 3.0.18` through the usual lineage.

## Validation

- Tranche: 38 tests in `test_site_rules_source` OK; `invoke ui-test` passes with row,
  half-row, Add row and text round-trip checks. The full gate runs inside `--write`.
- Not verified: a tag row against a live Forward tags endpoint in a browser, and a save
  round trip through the browser (the form field is unit-tested separately).

## Rollback

Revert the release: the textarea alone is the 3.0.17 behaviour, and saved rules are
unchanged.

## Decision Log

- Plugin-only release; customers already on 3.0.17 with republished queries need nothing
  else.
