# Release 3.0.5

## Goal

Close the gaps a customer's post-3.0.4 sync showed: the physical device, not a virtual system, owns a shared management address; the support bundle says which bare-primary-IP devices nothing explains; and the operator docs say which counts need action.

## Constraints

- No customer names, network IDs, snapshot IDs or hostnames in the repo, plans, tests or docs. Tests use synthetic names.
- NetBox allows one primary-IP owner per address (`UNIQUE(primary_ip4_id)`); no change may try to give two devices the same address.
- Existing primary-IP owners are never moved by the sync.
- Shipped NQE changes are paired with tests and reference-doc updates; customers on org-backed queries must run Publish Bundled Queries.
- Anything needing data not yet seen is investigate-first; no fix from a guess.

## Touched Surfaces

- `forward_netbox/queries/forward_ip_addresses_ipv4.nqe`, `forward_ip_addresses_ipv6.nqe`.
- `forward_netbox/views.py` (`_primary_ip_bundle_payload`).
- `forward_netbox/tests/test_ip_address_dedup_query.py`, `test_bundle_triage_diagnostics.py`.
- `docs/01_User_Guide/troubleshooting.md`, `docs/02_Reference/built-in-nqe-maps.md`.
- Release surfaces per `scripts/release.py`.

## Approach

1. **Physical device owns a shared address.** Each candidate IP row carries `virtual_rank` (1 when Forward's `device.system.physicalName` differs from the device name, else 0). Global (host IP) and VRF dedup choose the device among the lowest rank, then the lowest name. A virtual system or vdom wins only when no physical device holds the address. Verified read-only against a live network: row count and key set unchanged, one address moved from a virtual to a physical owner.
2. **Bundle accounts for the bare count.** `primary_ip.without_primary_ip_not_in_fallback_summary` is the bare count less the fallback summary's `left_without_primary_ip` (None without a summary).
3. **Docs.** A troubleshooting section maps each fallback bucket and the uncovered split (unclaimed vs owned quarantine) to an action.
4. **Untagged-VLAN ingestion issues: investigate first.** Read the bundle's `by_validation_rule` for the customer's three issues. `untagged-vlan-outside-device-site` points at `forward_interface_vlan_audit`; `untagged-vlan-needs-interface-mode` is a different path. A fix needs a failing test first.
5. **Release hygiene.** Move the netbox-dlm tested pin to 0.10.2 only when it is on PyPI, triage Dependabot alert 7, supply the real `FORWARD_SENSITIVE_PATTERNS` feed, remove stale release worktrees.

## Validation

- Query tests assert every candidate source ranks virtual devices and both dedups use the rank, for IPv4 and IPv6.
- Bundle tests cover the derived figure with and without a summary.
- `invoke harness-check`, `invoke lint`, `invoke check`, `invoke test`, `invoke docs`, then `invoke ci` via `scripts/release.py`.
- Live check against Forward that both queries compile and return the same key set as before.

## Rollback

Revert the commit. The queries return the same rows except for the owner of addresses shared between a physical and a virtual device; the bundle field is additive. Primary IPs already assigned stay.

## Decision Log

- A name-sorting rule in `primary_ip.py` was rejected: the IP query already gives each address to one device, so the primary-IP step could only ever pick that device. The right place to prefer the physical device is the query.
- `physicalName` is used rather than a name pattern: it is Forward's own statement of which chassis a context runs on, and it needs no vendor-specific naming rule.
- A Palo Alto chassis is not a device in Forward, so its contexts win by lowest name (`vsys1`).
- Devices whose management address is on no interface of any group member cannot get a primary IP from any sync rule; they are reported and documented, not fixed.
- Untagged-VLAN work stays investigate-first because the rule behind the customer's issues has not been read from the bundle.
