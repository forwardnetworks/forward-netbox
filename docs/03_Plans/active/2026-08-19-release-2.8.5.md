# Release 2.8.5

## Goal

Ship the change that makes a failed sync say what failed, plus two corrections
to machinery that reports on this repository's own work.

## Why

A deployment's sync failed after 36 minutes of staging and produced a support
bundle whose entire diagnostic content was the word `KeyError`: no model, no
row, no key, a `<redacted diagnostic>` job error and empty per-model failure
evidence. The failure is deterministic, so retrying costs another 36 minutes
and produces the same nothing.

That is the release. The other two entries are smaller and in the same family:
things that reported more confidence than they had earned.

## Constraints

- A patch. No migration, no shape change, and nothing that alters what a sync
  writes to NetBox.
- The redaction does not relax. This release makes a failure nameable when the
  name is demonstrably this repository's own vocabulary, and leaves it silent
  otherwise.
- `max_version` stays `4.6.99`. Unchanged from 2.8.4, and for the same measured
  reason: `netbox_branching` 1.1.2 does not import on NetBox 4.7.0-beta1.

## Touched Surfaces

Landed across three pull requests:

- `#246` the dependency preview reports what its comparison cost
- `#247` one declaration for the tested NetBox runtime, enforced by the harness
- `#248` a failed sync can be diagnosed

This commit adds the version surfaces, the compatibility tables, and this plan.

## Approach

### A KeyError is the one exception whose key is the diagnostic

`failure_reason` matches allowlisted slugs against exception text. A
`KeyError`'s text is only the key, so nothing matched and the classifier
collapsed to the class name. The key is also the token most likely to be
customer data, which is why it was withheld - and withholding it is what left a
customer with a 36-minute failure and nothing to act on.

The distinction needed was never "is this a string" but "did this repository
choose this name". `MODEL_SYNC_CONTRACTS` is exactly that set, so a key drawn
from its field names or model labels is now named and anything else stays
redacted. A device-name key is still silent, deliberately, even though it is the
one that would be most useful.

### The bundle reported failures that never happened

Warning bodies are redacted for the same reason failure bodies are. The
replacement sentence asserted that an operation had FAILED, which is a different
claim. Thirty of those appeared seconds into that run, one per model, each
pointing at failure evidence that was empty because nothing had failed - they
were the routine notice that a model cannot run a diff and still syncs.

Thirty invented failures is what had to be read past to find the one real
failure thirty-six minutes later.

### Two checks that now report their own limits

The preview measures drift on models it previously skipped, which is real work
on a converged estate. It cannot exhaust the job - every Forward job is floored
at 7200s and the full 1M-row merge projection is under 1800s - but the cost was
unknown, so the preview now reports it rather than anyone estimating it.

The tested-on NetBox version had thirteen hand-maintained pins and no source of
truth; the last uplift missed one written as an escaped regex, invisible to any
literal search. One declaration now exists and the harness names every pin that
disagrees with it, reading both forms.

## Validation

Recorded in the Release Authorization section below, bound to the evidence base
commit: the full isolated gate and the exact-runtime artifact test, both on the
final tree, both on NetBox 4.6.8.

## Rollback

No migration, so a downgrade is an install of the prior wheel. Every entry is
observational: reverting restores the previous reporting and changes nothing
about what a sync does.

## Decision Log

- **Ship the diagnosability fix before the defect it will diagnose.** The crash
  is unidentified and the bundle cannot narrow it. Releasing the naming first is
  what makes the next occurrence answerable, and waiting would cost the
  deployment another blind 36-minute run.
- **Patch, not minor.** Nothing gains an operator control and nothing changes
  shape.
- **No third item invented.** The remaining candidates from that support bundle
  were examined and rejected: `collection_gap` is rated correctly and is
  reporting a real, growing collection failure, and change-explainability
  truncation is already labelled where it is displayed.

## Open

- The crash itself. This release makes the next occurrence self-describing; it
  does not fix the sync, and the deployment must run once more to produce a
  named key.
- Whether the crash is specific to `ipam.ipaddress` is unknown. Thirty caught
  failures spread one per model suggest the shard where it finally escaped may
  not be where it originates.
- The comparison cost at a large deployment's scale is now observable and still
  unobserved.
