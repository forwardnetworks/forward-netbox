# Release 2.9.13

## Goal

Cut `2.9.13` on `maint/2.9.x`. Ships `#511`: two fixes found while a customer
ran `v2.9.12` against real production data - the site-relabel duplicate
repair crashing with a bare "ProtectedError" instead of a named refusal, and
SNMP endpoint IPv4 addresses always syncing as /32 instead of their real
subnet.

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `2.9.13` together, or `check_harness.py`
  refuses the release.
- The tested runtime is unchanged at NetBox `4.6.10`.
- No code change in this commit: the functional change already landed as
  `#511`, reviewed and gated on its own branch.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`.
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`,
  `CHANGELOG.md`.
- This plan.

## Approach

`scripts/release.py 2.9.13 --write` bumps every version surface and the
fast-baseline pin in the same commit and regenerates `CHANGELOG.md` from the
README compatibility table. The one commit it covers contains `#511`:

- **Site-relabel repair crash.** `netbox_peering_manager.PeeringSession.bgp_peer`
  is a one-to-one PROTECT FK on `BGPPeer`; deleting an allowlisted `BGPPeer`
  with a live session raised a bare `ProtectedError` the per-pair loop caught
  as a crash rather than a named refusal. `PeeringSession` joins the
  releasable allowlist, and the per-object delete is now recursive: an
  allowlisted object's own blockers are released first, in order.
- **Endpoint IPv4 /32-only addresses.** The query read only
  `ipAdEntIfIndex` from SNMP's `ipAddrTable`; it now also reads
  `ipAdEntNetMask` and converts the dotted mask to a real prefix length via a
  direct lookup table. An endpoint that answers no mask still gets /32, the
  same honest single-host default used elsewhere.

## Validation

- `#511`'s own `invoke ci` pre-push gate passed before merge: 118 new/changed
  tests plus the full suite, including the artifact-upgrade-test leg
  (2.9.11 on NetBox 4.6.5 -> 2.9.12 on NetBox 4.6.10, migrated with rows
  surviving).
- `scripts/release.py 2.9.13 --write` verify step: version-surface
  consistency, UI harness dependencies, advisories, Dependabot alerts,
  `poetry.lock` parity, `check_bundled_query_signatures`, `check_harness.py`,
  full `invoke ci` and `invoke artifact-test`.
- The PeeringSession fix was verified against an isolated test replicating
  the exact PROTECT chain, not a customer's database - Forward has no
  visibility into a customer's NetBox ORM. The netmask fix was verified
  against real data: prefix lengths on a real network now land at /8-/30
  instead of all /32 (1,551 real netmask entries read).
- The sensitive-pattern parity check runs UNVERIFIED in this checkout
  (`FORWARD_NETBOX_PATTERN_PARITY_UNVERIFIED` is set); the release gate
  applies the superset feed and can still refuse the tag.

## Rollback

This commit is a version bump and changelog entry only. Reverting it restores
the previous version surfaces; `#511` needs its own revert. Neither fix ships
a migration.

## Decision Log

- **Released as a focused patch**, not folded into unrelated work, because a
  customer is actively blocked on the duplicate-repair crash and the fix is
  small and independent.
- **Not held for the 4.7 line in this release.** The same fixes port to
  `main` as their own change after this one ships.
