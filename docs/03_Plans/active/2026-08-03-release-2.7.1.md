# Release 2.7.1

## Goal

Publish `2.7.1` carrying the field-reported fix tranche that landed after
`v2.7.0`, including the merge-delete prediction that `2.7.0` shipped as a
declared known limitation.

## Contract

- The four version surfaces move together in one commit: `pyproject.toml`,
  `forward_netbox/__init__.py`, the `fast_baseline` runtime pin, and
  `test_runtime_dependency_check`. Splitting them reverts the fast baseline
  from minutes to hours with no error.
- The three release-compatibility tables and the install document carry the
  same version, and `CHANGELOG.md` is generated from them rather than authored.
- Both release gates run against the final tree on a clean working tree, and
  the recorded command is the command that ran.
- Provenance verifies locally before the tag is pushed. A tag-time failure
  spends the version permanently, which is how `2.6.10` and `2.6.11` were lost.

## Constraints

- No migration and no operator step. Every fix in this tranche is behavioural.
- `netbox_branching` stays in the ingestion path.
- No new bundled query, so no organisation-library publish is owed for this
  release.
- The release row is the published release notes surface; it carries no
  customer identifiers.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`
- `forward_netbox/utilities/fast_baseline.py` (runtime pin)
- `forward_netbox/tests/test_runtime_dependency_check.py`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`
- `CHANGELOG.md` (generated)

## Approach

`scripts/release.py` owns the version and table edits, so the bump is executed
rather than hand-applied. The tranche itself is already on `main` and reviewed;
this release adds no behaviour. What remains is the gate, the authorization
record, the tag, and the close-out.

Merged since `v2.7.0`:

- Predict merge deletes blocked by hidden PROTECT references (#122)
- Fail when a post-release step is skipped (#123)
- Open the next development version correctly (#124)
- Make a release open its own close-out work (#125)
- Register the ingestion issue list route (#126)
- Order M2M targets created in the same merge before their referrers (#127)
- Let an ingestion take its own reconciliation rows with it (#128)
- Assert alias-variant coverage is complete and intentional (#129)
- Stop an unsatisfiable merge row presenting as a failed sync (#130)
- Take the `cryptography` fix for CVE-2026-69247 (#131)
- Audit dependencies before the gate, not after the tag (#132)

## Validation

The full local release gate and the exact-runtime artifact test, both run in an
isolated Docker project against NetBox 4.6.6 with Branching 1.1.2 on Python
3.14, recorded under Release Authorization below with their real outcomes.

## Rollback

Nothing to roll back before the tag exists. After publication, the recovery is
a forward release: the tranche is already on `main`, so a defect found in
`2.7.1` is fixed in `2.7.2` rather than by retracting an artifact consumers may
already have installed.

## Decision Log

- Released without the `phase` and `exception` columns from the field report
  that prompted the investigation into `#127`. An independent measurement at
  estate scale found zero ordering violations, showed `#127` fixed rather than
  introduced a cycle-guard defect, and placed the reported warnings before
  branch provisioning — upstream of the merge path entirely. Releasing was an
  explicit decision made with that evidence and that gap both understood.
- `release.py --write` was not used to run the gate, because it invokes the
  gate in a form the authorization checker does not accept, and recording a
  command that was not the one executed is the failure mode the checker exists
  to prevent. The prepare stage was invoked directly and the gate run
  separately in the accepted form.

## Open

- The stale ownership evidence that pins an ingestion indefinitely is a design
  question, not a defect, and is deferred to `2.7.2`.
- The `ipam.ipaddress` primary-ip-reassignment-blocked rejection remains a
  destination-side validation rule. `#130` stops it from wedging the baseline;
  it does not make the row acceptable.
