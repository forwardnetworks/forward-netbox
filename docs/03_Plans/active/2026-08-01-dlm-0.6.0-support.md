## Goal

Accept the optional `netbox-dlm` 0.6.0 release while retaining explicit,
validated runtime admission for the fast baseline, set-based merge, COPY/SQL,
and optional-plugin query execution.

## Constraints

- No InventoryItem/CIMC integration is included.
- Runtime allowlists remain explicit version sets and reject unvalidated
  releases.
- Verify live required-field drift and DLM migration `0004` under NetBox 4.6.6.

## Touched Surfaces

- Optional dependency range and tested constraints.
- DLM capability-version set and exact runtime allowlists.
- Version-admission tests.

## Approach

Add `0.6.0` only after validating the installed DLM package, its migration,
and the requested DLM/fast-baseline integration tests. The optional-plugin
registry retains its scalar compatibility field while DLM declares an explicit
supported-version set (`0.4.1`, `0.5.0`, `0.6.0`); single-version integrations
retain their existing exact-match behavior. Keep the new DLM models outside
Forward's supported model set.

## Validation

Run the requested DLM, catalogue-conflict, optional-version, integration,
fast-baseline, and provision-preflight tests in a project-isolated Compose
stack with DLM 0.6.0 installed. Run the live field-drift check and confirm
`netbox_dlm.0004` applies.

## Rollback

Revert this change; no Forward migration or persisted state is introduced.

## Decision Log

- `required_package_version` remains the scalar compatibility/API value. The
  registry now evaluates an explicit DLM supported-version set so validated
  0.4.1 and 0.5.0 customers are not silently skipped after 0.6.0 support is
  added.
