# Release 3.0.14

## Goal

Fix what the first customer bundle from 3.0.13 showed and what reproducing it on a customer-shaped estate found:

- Rows Forward stopped returning (interfaces, addresses, MACs, cables, BGP and OSPF rows) were never deleted when the set of in-scope devices changed in the same run, and were forgotten for good. A customer whose scope shifts most runs accumulated months of them.
- A preview-first cleanup removes the ones earlier releases already forgot.
- A device-scoped query that Forward stops at its own NQE time limit is fetched again in parts instead of failing its model (the customer's cables did not refresh).
- Include tags that match no collected device stop the run. Before, one such run deleted every platform (blanking it on every device), unused device types, and every OSPF area with its interfaces.
- A platform, manufacturer, role or device type still in use is never deleted.
- The Scope Reconciliation row a customer read as the uncovered count is relabelled.

## Constraints

- No customer names, network ids, snapshot ids, hostnames or addresses in the repo, plans, tests or docs.
- No shipped NQE query change, nothing to republish. No migration.
- Deletes fail closed: device deletes stay with the prune quarantine; rows of devices that left scope are carried, never judged; the cleanup deletes only rows the sync created and nobody else changed, through the sync's own delete adapters, after a preview.
- `development/constraints-upgrade-from.txt` forward-sdk pin moves to 0.1.35 only in the release step (the pre-push upgrade gate reads it).

## Touched Surfaces

- Scope-change deletes: `workload_state.py` (`_scope_device_names`, `_legacy_parameter_hash`, `CARRIED_ROW_HASH`), `query_fetch_execution.py` (durable-state log and diagnostic). Plan: `2026-11-06-scope-change-still-deletes.md`.
- Time-limit split: `query_fetch_execution.py` (`_fetch_spec_rows_splitting_on_time_limit`, `TIME_LIMIT_SPLIT_REFUSED_MODELS`). Plan: `2026-11-07-split-fetch-on-nqe-time-limit.md`.
- Stale-row cleanup: `stale_row_cleanup.py`, `jobs.py`, `sync_facade.py`, `api/views.py`, `views.py`, Scope Reconciliation template, bundle fields. Plan: `2026-11-07-stale-row-cleanup.md`.
- Empty scope and catalogue deletes: `query_fetch_execution.py` (`_resolve_scoped_tag_scope(refuse_empty=True)`), `sync_primitives.py` (`SHARED_CATALOG_MODELS`), `diagnostics.py` (`include-tags-match-no-device`). Plan: `2026-11-07-empty-scope-and-shared-catalogue-deletes.md`.
- Label: template, `reconciliation_strip.py`, `bundle_label_index.py`, `bundle_ui_figures.py`, `health.py`, troubleshooting guide.

## Approach

1. Each fix landed with tests derived from the symptom, a code-reviewer audit, and a live run on the customer-shaped stack.
2. Full Django suite on the final tree, then `scripts/release.py 3.0.14` through the usual lineage.
3. After the tag nothing needs republishing. The customer upgrades; the first run after upgrading whose scope changed resets once (the 3.0.13 state cannot be compared), every later run deletes normally; then Scope Reconciliation -> Preview stale rows -> Remove.

## Validation

- Full Django suite on the final tree on the test host: 4463 tests OK (33 skipped).
- Live, customer-shaped estate (about 3,900 devices, 150k BGP peers), read-only Forward:
  - A scope change of 3,858 -> 3,814 devices: every device-scoped model stayed `local_delta` and deleted what Forward stopped returning (13,230 interfaces, 3,544 cables, 450 BGP peers, 151 addresses), carrying the rows of devices that left scope; merge 0 failures. Before the fix the same change deleted nothing.
  - Stale-row cleanup through the UI with agent-browser: preview 174 removable (158 BGP peers, 11 interfaces, 5 cables), 198 held (management-step interfaces, primary and per-context addresses); removal deleted exactly those 174; the next syncs merged with no failures.
  - Include tag set to a name no device carries: the run stops with `ForwardQueryError: include-tags-match-no-device` and changes nothing (before: all platforms, 58 device types, a role and all OSPF areas deleted).
- Unit tests only: the time-limit split (Forward cannot be made to time out on demand). Say so in the release notes.
- Not verified: the cleanup on a NetBox whose change log retention dropped the create records (those rows are held, by design).

## Rollback

Revert the release. Nothing is migrated. Durable states written by 3.0.14 carry a new parameter hash for device-scoped models; 3.0.13 reads them as a parameter change and resets once.

## Decision Log

- The scope-change bug: the in-scope device names are pushed into device-scoped queries as `forward_netbox_shard_keys`, and those names were part of the durable-state parameter hash, so any scope change took `contract_reset`, which deletes nothing and replaces the stored state.
- Rows of a device that left scope are carried with a blank hash: a review showed that carrying them as current would leave a device pruned while out of scope with no interfaces when it returns.
- IP and MAC queries are never split on the time limit: they pick one owner per address across devices, and halves would pick their own.
- The cleanup's first device list (identity records and scope claims) judged no device live: scope claims exist only with "apply device scope tags" on. It now uses the latest run's `dcim.device` state.
- The empty-scope refusal first keyed on the whole scoped set; review showed unscoped SNMP endpoints keep it non-empty after a renamed tag. It keys on collected devices.
- During live testing an rsync replaced the test host's `development/secrets` (same timestamps, different contents); the dev stack was recovered from the running containers. Test-host procedure only, nothing shipped.
