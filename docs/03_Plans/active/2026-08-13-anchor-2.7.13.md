# Advance the release provenance anchor to 2.7.13

## Goal

Complete the post-release bookkeeping for 2.7.13: pin the anchor to the tag and
its documentation bridge, and tell operators that 2.7.13 is what they should be
running - which matters more than usual, because 2.7.12 deletes devices on
every full run.

## Constraints

- The bridge is fixed at the first commit after the tag; the anchor can only
  pin `21870ef`.
- Exactly one row in each of the three tables may say "Current release".
- Local `verify_release_provenance.py` cannot run to completion on this host;
  the publish workflow runs the identical verifier and is fail-closed.

## Touched Surfaces

- `scripts/verify_release_provenance.py` (anchor pair)
- `scripts/check_harness.py`, `scripts/tests/test_tasks.py` (prior-tag literals)
- `.github/workflows/release.yml` (tag fetch)
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`

## Approach

Mechanical, the same shape as every prior anchor advance: the five
hand-maintained copies of the prior tag move together, and the tables promote
2.7.13 and demote the outgoing release in the same change.

## Validation

`scripts/check_harness.py` - including the check that the anchor is not behind
the table - and the full `scripts/tests` suite.

## Rollback

Revert. The anchor returns to `v2.7.12` and the tables call 2.7.12 current,
which would recommend the release that deletes devices.

## Decision Log

- **Promote and re-anchor in one change**, as always: each half is silent on
  its own, and the harness ties them together.

## Open

- Nothing for 2.7.13.
