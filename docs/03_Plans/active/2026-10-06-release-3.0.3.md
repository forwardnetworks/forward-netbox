# Release 3.0.3

## Goal

Cut `3.0.3` on `main` (the NetBox 4.7 lane). It carries everything that landed
after `3.0.2`, driven by a customer's first sync on 3.0.2 and its support
bundles: global-table static routes that never imported, site-relabel repair that
could not release BGP address families, primary IPs left unset when a management
tag could not resolve, interfaces refused on every sync because of a VLAN from a
previous site, a `scrapli` release that stopped NetBox starting next to
`netbox-validity`, and OSPF instance names that collided under `netbox-routing`
0.5.0. It also moves the tested runtime to NetBox `4.7.2` and
`netbox-branching` `1.2.1` and adds the figures those reports could not be
answered from.

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `3.0.3` together.
- The tested runtime is NetBox `4.7.2` and `netbox-branching` `1.2.1`;
  `min_version` stays `4.7.0`.
- The artifact-upgrade leg seeds the from-side (`3.0.2`) on NetBox `4.7.0`
  through the 3.x from-side default already on `main`.
- No code change in this commit: every functional change already landed as `#528`,
  `#530`, `#532` and `#533`, each gated on its own branch.

## Approach

`scripts/release.py 3.0.3 --write` bumps every version surface and the
fast-baseline pin in one commit and regenerates `CHANGELOG.md` from the README
compatibility table. The changes it covers:

- **`#528`.** A null `vrf` identifies a global-table static route, so those routes
  import (a customer's 6,738 of 9,206 configured routes were skipped wholesale);
  site-relabel repair releases `bgpaddressfamily` objects before deleting a
  duplicate device; the primary-IP fallback now also covers devices whose
  `Mgmt_` tag did not resolve, and the job log says why each device stayed
  unresolved; the 3.x upgrade-test from-side defaults to NetBox `4.7.0`.
- **`#530`.** The dev and test gates rerun a stage from a clean database when the
  NetBox image's interpreter crashes, and the earlier GC hook is reverted.
- **`#532`.** `scrapli` is capped below 2026.10 in the `validity` and
  `integrations` extras (2026.10.3 removed `AsyncDriver`); OSPF instances carry the
  VRF in their name, so `netbox-routing` 0.5.0's unique (device, name) holds; the
  tested runtime moves to NetBox `4.7.2` and `netbox-branching` `1.2.1`. Its one
  finding: deleting a cable now records the interface's cable-cache clear as its
  own UPDATE audit row, so one merge test expects five rows instead of four.
- **`#533`.** An interface holding an untagged VLAN from a previous site has it
  cleared instead of being refused on every write. The support bundle gains
  dependency versions, the scope report's age, a split of devices without a primary
  IP, a mask breakdown of primary IPv4 addresses, per-model and per-rule issue
  counts, OSPF name collisions, and `site_mismatch` in the scope report (which
  makes Refresh Scope Reconciliation read the sync's device map every time: one
  more Forward call per refresh).

## Rollback

This commit is a version bump and changelog entry only. Reverting it restores the
previous version surfaces; each merged change needs its own revert. None carries a
migration.

## Decision Log

- **Previous optional-plugin releases are not accepted on this lane.** This lane
  validates one release of each optional plugin on NetBox 4.7 and no gate has run
  older ones, so widening the ranges would claim versions that are untested here.
- **The scope report always reads the device map.** Telling a stale placement from
  a current one needs Forward's site for every device, not only duplicated names; an
  extra Forward call on an operator-triggered refresh is the cost.
- **An OSPF duplicate that already exists in a database cannot be repaired by this
  plugin.** It fails inside `netbox-routing`'s own migration before this plugin
  runs, so the release notes carry the one-time rename.
