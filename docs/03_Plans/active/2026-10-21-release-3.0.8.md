# Release 3.0.8

## Goal

Ship the batch of follow-ups to 3.0.7 (PR 572): every count an operator is left wondering about carries a reason, a fixable label, a suggested action and a link or button. Counts explained on Health and in the support bundle, one page for every device without a primary IP, device and module types NetBox already holds reused instead of look-alikes created, the types the sync created listed with the equivalent to move to, a device-numbers strip, a reading guide and a "What it means" column on the drift table, a button that tags BGP neighbour addresses, and collecting a snapshot from a change behind a warning and an access check.

## Constraints

- No customer names, network IDs, snapshot IDs, hostnames or addresses in the repo, plans, tests or docs. Tests use synthetic names.
- No shipped NQE query, no migration and no runtime dependency changes in this release, so there is nothing to republish and nothing to migrate.
- The release tool lock moved to certifi 2026.10.19, virtualenv 21.14.12 and packaging 26.3 because the release preflight refuses locks that carry a known advisory.
- Explanatory text states what the figures are and nothing about what a sync will do; four audits rejected earlier drafts for sentences the code contradicts.

## Touched Surfaces

- `forward_netbox/utilities/` explained_findings, primary_ip_reasons, skip_reason_catalogue, bgp_neighbour_ips, netbox_type_matching, sync_created_types, reconciliation_strip, drift_explanations, scope_reconciliation, query_fetch_execution, dlm_notice_audit, health, sync_facade, change_control/workspace.
- `forward_netbox/views.py`, `jobs.py`, REST actions, the Health, explained, types and drift report templates.
- `requirements-release.txt` and the release surfaces written by `scripts/release.py`.

## Approach

1. PR 572 merged to `main` after the full pre-push gate passed on its tip.
2. Run `scripts/release.py 3.0.8` through the usual lineage: cut, authorize, evidence, tag, post-release bridge, anchor.
3. After the tag, nothing needs republishing. Customers with a pinned older plugin upgrade and re-sync; the Health page then shows Counts explained and the device-numbers strip.

## Validation

- `invoke ci` on the pushed tip of PR 572 (passed, including the artifact upgrade test 3.0.6 -> 3.0.7) and again on the release tree via `scripts/release.py`.
- `pre-commit run --all-files`, `invoke harness-check`, `scripts/check_operator_text.py` and the script tests.
- Each feature ships tests derived from its requirement, including a fetch-wiring test for type matching and a page render test for the drift table.
- Not verified: collecting a snapshot against live Forward (it logs in to devices; it needs a throwaway workspace and explicit approval), and the type matching against the reporting customer's own NetBox.

## Rollback

Revert the release. Type matching only stops new look-alike types; nothing it did needs undoing. The tag button and Counts explained are read-only apart from the tag the operator applies.

## Decision Log

- Explanations define the drift figures as the preview's estimates and promise nothing about what a sync stages: removals are clamped between what Forward declares and what the durable state stages, and a first sync stages every row.
- A matched device type's own row is dropped, so a library type is never written and no library identity reaches durable workload state.
- The release-only sensitive-pattern feed is a GitHub secret and cannot be read locally, so the cut runs with the parity bypass and relies on the local scanner and synthetic fixtures; the release workflow runs the real feed at tag time.
