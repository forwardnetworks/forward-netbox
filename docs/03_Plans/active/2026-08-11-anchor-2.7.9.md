# Advance the release provenance anchor to 2.7.9

## Goal

Complete the post-release bookkeeping for 2.7.9: pin the anchor to the tag and
its documentation bridge, and tell operators that 2.7.9 is what they should be
running.

## Contract

- The anchor pins `v2.7.9` and the bridge commit that follows it, `9c3a37b`.
- The five hand-maintained copies of the prior tag move together.
- The compatibility table promotes 2.7.9 and demotes 2.7.6 in the same change,
  so the anchor and the table agree again.

## Constraints

- The bridge is fixed at the first commit after the tag and cannot be
  reclaimed, so the anchor can only pin `9c3a37b`.
- Exactly one row in each of the three tables may say "Current release".
- Local `verify_release_provenance.py` cannot run to completion on this host;
  the publish workflow runs the identical verifier and is fail-closed.

## Touched Surfaces

- `scripts/verify_release_provenance.py` (anchor pair)
- `scripts/check_harness.py`, `scripts/tests/test_tasks.py` (prior-tag literals)
- `.github/workflows/release.yml` (tag fetch)
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`

## Approach

Mechanical, and the same shape as every prior anchor advance. The one thing
worth noting is what it restores: while the anchor sat at `v2.7.8` it named a
tag that published nothing, which is why `UNPUBLISHED_RELEASE_TAGS` had to
exist. With `v2.7.9` both published and promoted, the anchor and the table name
the same version again and the exception is no longer being exercised.

`UNPUBLISHED_RELEASE_TAGS` keeps its three entries. It is a record of which tags
never published, not a list of active exemptions, and `v2.7.3`, `v2.7.7` and
`v2.7.8` did not publish regardless of where the anchor points.

## Validation

`invoke ci` locally, which runs the harness - including the check that the
anchor is not behind the table - and the full `scripts/tests` suite.

## Rollback

Revert. The anchor returns to `v2.7.8` and the table calls 2.7.6 current, which
would then be wrong on both counts.

## Decision Log

- **Promote and re-anchor in one change.** Splitting them is how the anchor went
  stale before: each half is silent on its own, and the harness ties them
  together precisely so that neither can be skipped quietly.
- **Keep the unpublished-tag record rather than empty it.** The next burned tag
  will need the same mechanism, and a list that is cleared whenever it happens
  to be unused loses the history of why it exists.

## Open

  the preflight scan runs for real instead of being acknowledged.
