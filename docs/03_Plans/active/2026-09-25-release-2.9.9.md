# Release 2.9.9

## Goal

Cut `2.9.9` on the `maint/2.9.x` lane. It closes the gap the case-insensitive
device-identity fix in `v2.9.8` left open - a site relabel alone still
duplicated the device - ships the GUI repair for pairs the bug already
created, makes scope reconciliation and pending-removal counts trustworthy
per device rather than per name or per query map, adds a standing warning for
the class of published-query-signature outage `v2.9.7` caused, and gives an
instant config-backup failure a stage name instead of a bare exception.

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `2.9.9` together, or `check_harness.py`
  refuses the release.
- The tested runtime is unchanged at NetBox `4.6.10`; the new table rows say
  so.
- No code change in this commit beyond the version bump and changelog: all
  eight functional changes already landed as their own reviewed, `invoke
  ci`-green PRs.
- No customer names, identifiers, or scan-matching hostnames in this plan,
  the changelog entry, or the release commit message.
- `scripts/check_bundled_query_signatures` (new in this tranche, #468) must
  pass clean: this release changes no `@query` parameter list, so the
  changelog carries no "Publish Bundled Queries" instruction and none is
  needed.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`,
  `CHANGELOG.md`
- this plan

## Approach

`scripts/release.py 2.9.9 --write --summary "..."` bumps every version
surface and the fast-baseline pin in the same commit and regenerates
`CHANGELOG.md` from the README compatibility table. The eight commits it
covers (oldest to newest, all already merged to `maint/2.9.x`):

1. **The support bundle answers what an investigation had to script**
   (`12e74c1a`, #462) - a `diagnostics` section (uncovered-device causes,
   identity bindings, rename/case-collision counts, NQE map bindings,
   ingestion-issue detail) and `duplicate_device_names`, closing the gap that
   previously took a hand-written diagnostic script to answer.
2. **Config backup delivery status joins the support bundle**
   (`deeec38f`, #463) - `ConfigBackupError` messages are preserved verbatim
   into `job.data["error"]` instead of collapsing to a bare exception name;
   `config_backup_delivery` (value-free) joins the bundle.
3. **Move a device instead of duplicating it when Forward relabels its site**
   (`a707ff7c`, #464) - the actual root cause of the customer's 248 duplicate
   pairs: `(name, site)`-only matching treated a Forward site relabel as a
   new device. Device identity is now resolved by name first, and a
   single-candidate, unambiguous match moves the existing device.
4. **GUI repair for existing site-relabel duplicate pairs**
   (`c60e9521`, #465) - a new Scope Reconciliation action, **Merge
   site-relabel duplicates**, detects safe pairs (exactly 2 devices, same
   casefolded name, different sites, no operator-owned objects on the newer
   copy) and merges them, keeping the older device at the new site.
5. **Scope reconciliation is site-aware, not just name-aware**
   (`379a622e`, #466) - out-of-scope, orphan and uncovered detection are now
   keyed by device pk with a site-aware test, not by name alone, and exclude
   any pk still in an unmerged relabel pair so prune never removes a device
   the operator hasn't repaired yet.
6. **Pending-removal counts shown once, not duplicated per map**
   (`235bf804`, #467) - a model touched by more than one query map no longer
   multiplies its removal count once per map in the dependency preview and
   drift report; the first map gets the diagnostic, siblings are marked
   shared.
7. **Published-query signature drift: Health warning and release gate**
   (`37a13a8c`, #468) - a Health warning fires from already-stored
   `last_live_drift` state when a bundled query's live signature no longer
   matches what NetBox last confirmed (the class of outage that hit
   org-backed `v2.9.7` upgraders); a new release-preflight check refuses to
   ship an `@query` parameter change with no changelog mention.
8. **Config backup names its pipeline stage on failure**
   (`725cf908`, #469) - `ConfigBackupError` now prepends which of seven
   named stages (`resolve`, `fetch_remote`, `branch`, `nqe_fetch`, `build`,
   `push`, `datasource_sync`) it failed in, so a future instant failure names
   itself instead of needing a diagnostic script run by hand.

Higher-risk pieces from the originating plan were deliberately deferred, not
built here: a live signature check at sync start (item 5's Decision Log), and
an on-demand config-backup connectivity-probe button with its own persisted
field and migration (item 6's Decision Log). Both remain candidates for a
future release.

## Validation

- `invoke ci` passed on each of the eight PRs before merge, each with its own
  plan doc and targeted regression tests.
- `scripts/release.py 2.9.9 --write --summary "..."` verify step: version-
  surface consistency, UI harness dependencies, advisories, Dependabot
  alerts, `poetry.lock` parity, `check_bundled_query_signatures` (clean - no
  `@query` change in this tranche), `check_harness.py`, full `invoke ci` and
  `invoke artifact-test`.
- The sensitive-pattern parity check runs UNVERIFIED in this checkout
  (`FORWARD_SENSITIVE_PATTERNS` is a CI-only secret); the release gate
  applies the superset feed and can still refuse the tag.

## Rollback

This commit is a version bump and changelog entry only. Reverting it
restores the previous version surfaces; the eight functional PRs need their
own reverts. No migration ships in this release.

## Decision Log

- **Released as one batch of eight rather than per-item.** Every item is
  part of the same customer-facing repair (the site-relabel duplication bug,
  its GUI fix, and the diagnostics that would have shortened finding it) or
  closes a gap the same investigation surfaced; there is no reason to make
  the customer upgrade eight times for one incident's fallout.
