# Release 3.0.6

## Goal

Ship the subinterface fix (PR 557) and accept netbox-validity 3.6.1 (PR 558): an address on a subinterface attaches to that subinterface, not its parent, and the interfaces query returns every column the apply reads.

## Constraints

- No customer names, network IDs, snapshot IDs or hostnames in the repo, plans, tests or docs. Tests use synthetic names.
- Both shipped queries change (`forward_interfaces.nqe`, `forward_ip_addresses_ipv4.nqe`, plus IPv6). A map pinned to a direct query ID keeps the old text until the operator runs Publish Bundled Queries, so the release note and the post-release step say so.
- netbox-validity 3.6.0 stays accepted; 3.6.1 is the required and tested version.
- The first sync after publishing writes `lag`, `mode`, `untagged_vlan`, `mtu`, `speed` and `description` for the first time (the SNMP endpoint branch of the interfaces query had been stripping them). The release note says so.

## Touched Surfaces

- `forward_netbox/queries/forward_interfaces.nqe`, `forward_ip_addresses_ipv4.nqe`, `forward_ip_addresses_ipv6.nqe`.
- `forward_netbox/utilities/apply_engine_bulk.py`, `sync_interface.py`.
- Optional-plugin pins for netbox-validity (`pyproject.toml`, constraints, lockfile, validated runtime, integration registry).
- `docs/00_Project_Knowledge/release-playbook.md` (post-release query publish step), troubleshooting and built-in maps docs.
- Release surfaces per `scripts/release.py`.

## Approach

1. Cut after PRs 557 and 558 merged to `main`; each passed the full local gate on its own branch.
2. Run `scripts/release.py 3.0.6` through the usual lineage: cut, authorize, evidence, tag, post-release bridge, anchor.
3. After the tag, publish the bundled queries to the reporting customer's Forward org and have them re-sync. The plugin release must precede the publish: the previous plugin ignores `parent`, and a published query would otherwise leave unlinked interfaces.

## Validation

- PR 557: two independent diff audits (six defects found and fixed with tests), live read-only checks of the changed queries on a 40-device sample, and the full gate.
- PR 558: an image built with 3.6.1 confirmed to install `netbox-validity 3.6.1` and `scrapli 2026.2.20`; the version, integration, validated-runtime, fast-path and config-backup tests pass there; the full gate passed.
- `invoke ci` on the release tree via `scripts/release.py`.
- Not verified: a real NetBox branch merge of a subinterface link (the tests mock the change recording), and the reporting customer's own VRF-subinterface switch.

## Rollback

Revert the release and republish the previous queries. Subinterfaces already created stay as ordinary interfaces and are removed by the normal absent-row delete path once the queries stop emitting them, child before parent.

## Decision Log

- No source setting for subinterfaces: only 21,343 of over a million subinterfaces on the measured network carry an address, so emitting only those grows the interface count by about 3.6%. A setting would also make the published query require a parameter the previous plugin never sends, which fails the sync.
- The release-only sensitive-pattern feed is a GitHub secret and cannot be read locally, so the cut runs with the parity bypass and relies on the local scanner and synthetic fixtures; the release workflow runs the real feed at tag time.
