# Advance the release provenance anchor to 2.8.5

## Goal

Point the anchor at `v2.8.5` and its bridge, and promote the release in the
compatibility tables.

## Why

A stale anchor grows the reviewed commit range on every release until GitHub
expires the oldest checks inside it, and the harness fails while the anchor
disagrees with the release the table calls current.

## Constraints

- The anchor tag and the README "Current release" row must name the same
  version.
- The bridge must be the first first-parent commit after the tag, parented to
  the release commit, and documentation-only.

## Touched Surfaces

- `scripts/verify_release_provenance.py` - the anchor pair
- `.github/workflows/release.yml`, `scripts/check_harness.py`,
  `scripts/tests/test_tasks.py` - the tag each pins
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`

## Approach

The bridge for `v2.8.5` is `066a629`, generated by `scripts/release.py` and
containing exactly one file. Verified with the release verifier's own predicate
rather than by eye, which is the second release running that way and the second
where the generated bridge needed no exception.

`BRIDGE_CONTENT_EXCEPTIONS` stays empty. It was emptied when the anchor passed
the `v2.8.3` bridge it existed for, and nothing since has needed one.

## Validation

`check_harness.py`, which runs the verifier's bridge rule against the pinned
pairing, plus the harness suite.

## Rollback

Revert. The anchor returns to `v2.8.4` and the harness fails on the promoted
table.

## Decision Log

- **Advance in the same session as the release.** The bridge slot is claimed by
  whatever lands first after the tag, and leaving the anchor stale is how the
  reviewed range grows until a release fails on an expired check.

## Open

- The transport timeout in `verify_github_release_controls` has now cost three
  release-command runs across two versions. It fails before the tag exists, so
  it is safe, but a bounded retry around `_github_json` would stop it costing a
  cycle each time. Not changed here: altering release machinery during a release
  is how the bridge broke.
