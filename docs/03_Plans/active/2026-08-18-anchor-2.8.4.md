# Advance the release provenance anchor to 2.8.4

## Goal

Point the anchor at `v2.8.4` and its bridge, promote the release in the
compatibility tables, and retire the exception that `v2.8.3` needed.

## Why

A stale anchor grows the reviewed commit range on every release until GitHub
expires the oldest checks inside it, and the harness fails while the anchor
disagrees with the release the table calls current.

## Constraints

- The anchor tag and the README "Current release" row must name the same
  version.
- The bridge must be the first first-parent commit after the tag, parented to
  the release commit, and documentation-only.

## Touched Surfaces

- `scripts/verify_release_provenance.py` - anchor pair, and the retired
  exception table
- `.github/workflows/release.yml`, `scripts/check_harness.py`,
  `scripts/tests/test_tasks.py` - the tag each pins
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`
- `scripts/tests/test_verify_release_provenance.py`

## Approach

The bridge for `v2.8.4` is `a3450f6`, generated by `scripts/release.py` rather
than written by hand, and it contains exactly one file. Checked with the
verifier's own predicate rather than by eye:

    DOC   docs/03_Plans/active/post-release-2.8.4.md
    bridge qualifies: True

### The v2.8.3 exception is deleted, not carried

`BRIDGE_CONTENT_EXCEPTIONS` existed for exactly one release. It excused
`1d64c34` for carrying four version surfaces, keyed by commit hash, because the
bridge slot is immutable and that commit could not be repaired.

With the anchor now on `v2.8.4`, that entry is never consulted again. Keying by
hash is what makes an exception expire on its own, and a dead excuse for a
provenance rule should not sit in the file waiting to be copied by someone who
needs one. The table is now empty, and a test pins it empty.

The stage that produced the bad bridge has been fixed, so the next entry should
never be needed. The tests still pin the shape one would have to take: a full
commit hash, exact paths, no globs, no directories.

## Validation

`check_harness.py`, which runs the verifier's own bridge rule against the
pinned pairing. The harness suite, including the rewritten exception tests.

## Rollback

Revert. The anchor returns to `v2.8.3` and the harness fails on the promoted
table.

## Decision Log

- **Delete the exception in the same commit that makes it dead.** Coupling them
  means it cannot be forgotten, and the alternative is a permanent hole that
  looks like precedent.
- **Keep the shape tests after emptying the table.** They are the part that
  matters if anyone ever adds a second entry.
