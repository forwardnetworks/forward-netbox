# Release 2.9.2

## Goal

Ship the consolidated tranche: an exact drift comparison for every fetched
model, the uncovered-device count made answerable and warned on, five delete
and diagnostic defects closed, and a release that runs in one command.

## Constraints

- Runtime pins do not move. NetBox `4.6.x` (tested `4.6.8`), netbox-branching
  `1.1.x` (tested `1.1.3`). A 2.9.x release, not a minor: no operator-facing
  contract changes and no migration.
- 2.9.2 is the integration test for its own release tooling. It runs through
  `--auto-finish`; a failure there is fixed and resumed with the named flag,
  not hand-driven around.
- NetBox 4.7 stays out. It needs netbox-branching `>= 1.2.0`, and `1.2.0b1`
  is a beta.

## Touched Surfaces

Seventeen merged pull requests, #219 through #327, across the drift
comparison, scope reconciliation, health, the delete paths, the diagnostics
and the release tooling. Each carries its own plan in
`docs/03_Plans/active/`.

## Approach

Ordered so each tranche was independently mergeable and independently
revertable: dependencies and the alert gate first; the release tooling second,
so this release exercises it; the twelve-PR drift stack third; then the
customer-facing work, the delete paths, and the diagnostics.

Two defects were found by the work rather than reported: `ForwardQueryError`
took no keyword arguments while two callers passed them, aborting a whole
model's apply on one malformed row; and an absent parent under a preview
resolved to an unrelated sibling, which would have reported a confident zero.
Both are fixed with the slices that found them.

One defect was introduced and caught here: a source-form parameter added
without its validator allowlist entry, which made every source save fail. It
is fixed in #324 with a parity test comparing the two lists, because they were
two hand-maintained spellings of one fact.

## Validation

Recorded in the Release Authorization section below, rendered by
`scripts/release.py --authorize` from the evidence the gate itself wrote.

Before the release branch existed, the full Django suite ran green on merged
`main` at 2576 tests with 9 skipped, and every merged pull request carried its
own targeted suites plus `invoke harness-check`.

## Rollback

Revert to 2.9.1. No migration ships: the new `UNCOVERED` claim type is a
`choices` change, which Django 6.0 does not treat as schema state, so
`makemigrations --check` is clean in both directions.

## Decision Log

- **One release, not two.** The drift work and the customer-facing work share
  the preview and scope-reconciliation surfaces; splitting them would have run
  two forty-minute gates over the same code.
- **The release tooling landed first on purpose.** Its own plan says 2.9.2 is
  its integration test, and tooling that ships after the release it was meant
  to fix has proved nothing.
- **Three long-open items were closed by verification, not by code**:
  undeletable ingestions (#45/#46), narrowed-head detection, and the ownership
  refusal banner. Each was already fixed and each plan still said otherwise,
  which is its own defect - a closure nobody can see gets re-investigated.
- **C7, C8 and C9 are deliberately not in this release.** All three change
  merge-path classification, and each plan says it needs its own blast-radius
  review. Adding them to the end of a long tranche is how a customer loses
  rows.

## Open

- C7 (#39/#50 merge validation disposition), C8 (hidden-PROTECT merge
  predictor) and C9 (re-pointed maps orphan rows), each with its own recorded
  design note.
- NetBox 4.7, blocked on netbox-branching.
