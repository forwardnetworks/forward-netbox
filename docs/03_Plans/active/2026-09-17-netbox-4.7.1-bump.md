# Move the tested runtime from NetBox 4.7.0 to 4.7.1

## Goal

Bump the declared tested-on NetBox patch release from `4.7.0` to `4.7.1` on
the 3.x lane. `4.7.1` is a published patch release of the same `4.7` series
this plugin already targets (`min_version = "4.7.0"`, unchanged), not a
series move, so this carries none of the `4.6` -> `4.7` runtime-gate
implications the earlier `2026-09-02-netbox-4.7-runtime.md` plan covered.

## Constraints

- **`min_version` stays at `4.7.0`.** It is the declared floor, not the
  tested-on ceiling; `4.7.1` satisfies it. Per `scripts/tested_runtime.py`'s
  own docstring, historical/floor mentions like this are deliberately not
  swept by the tested-runtime pin check.
- **`scripts/tested_runtime.py` is the single declaration.** Bump
  `TESTED_NETBOX_VERSION` there first; `scripts/check_harness.py`'s
  `_check_tested_runtime_pins_agree` names every other site that still
  disagrees, including the escaped-regex form the `4.6.8` uplift missed.
- No plugin behavior changes with this release; this is a pin move only.

## Touched Surfaces

- `scripts/tested_runtime.py` (`TESTED_NETBOX_VERSION`)
- `development/Dockerfile`, `development/docker-compose.yml`
- `scripts/validate_sbom.py`, `scripts/validate_installed_artifact.py`,
  `scripts/check_release_authorization.py` (both the literal `NETBOX_VER`
  pins and the regex-matched evidence-text pattern for
  `exact-runtime-artifact`)
- `tasks.py` (default `NETBOX_VER` and the two release-artifact-validation
  guards)
- `scripts/release.py` (the `--requirements` help-text example only, cosmetic)

## Approach

Edit `scripts/tested_runtime.py`'s `TESTED_NETBOX_VERSION` to `"4.7.1"`,
then run `python scripts/check_harness.py` and fix every site it names. This
found one form a plain-text `grep -rn "4.7.0"` search would have missed:
`check_release_authorization.py`'s `EVIDENCE_REQUIRED_TEXT_PATTERNS`
compiles `re.compile(r"\bNetBox\s+4\.7\.0\b", ...)` to check that release
evidence text mentions the tested version by name - this needed the same
bump as the literal `NETBOX_VER` pins in the same file.

## Validation

- `python scripts/check_harness.py` - passed after all sites were updated.
- Docker image builds and boots healthy on `v4.7.1`.
- `manage.py check` clean.

## Rollback

Revert this branch. No migration, no persisted state, no runtime-gate
change - purely a tested-version pin.

## Decision Log

- **A patch bump, not a series move.** `4.7.1` is still series `4.7`, so
  `validated_runtime.py`'s series gates (`VALIDATED_NETBOX_SERIES`) and
  `min_version` need no change - only the exact tested-on pins do.
