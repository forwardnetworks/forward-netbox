# Close out 2.7.1

## Goal

Finish the post-release steps for the shipped `v2.7.1`: promote the release
table, advance the provenance anchor, and open `2.7.2.dev0`.

## Contract

- The release table and the provenance anchor move in the SAME change. The
  harness requires the anchor to track the current release, so splitting them
  leaves `main` red.
- The four version surfaces move together, or the fast baseline silently
  reverts from minutes to hours.
- This change is deliberately NOT the post-release bridge. The bridge slot is
  already held by the archive-only commit `8480bdc`, which is documentation
  only. That ordering is required, not stylistic.

## Constraints

- The anchor is hardcoded in SIX coupled places: `PRIOR_RELEASE_TAG` and
  `PRIOR_POST_RELEASE_DOC_COMMIT` in the verifier, the tag fetch in
  `release.yml`, two literal assertions in `check_harness.py`, a workflow
  fixture in `scripts/tests/test_check_harness.py`, and an assertion in
  `scripts/tests/test_tasks.py`. All six must move together or the next release
  fails at the tag, when the version is already spent.
- `check_harness.py` reads the real workflow, so it passes locally while the
  two fixture-based tests still fail. Only `python3 -m unittest discover -s
  scripts/tests` catches that pair; running the harness alone is not enough.
- No customer identifiers.

## Touched Surfaces

- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`
- `scripts/verify_release_provenance.py` (anchor)
- `scripts/check_harness.py` (tag assertions)
- `.github/workflows/release.yml` (prior-tag fetch)
- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`

## Approach

Promotion and the anchor advance are driven by the existing helpers rather than
hand-applied. The anchor moves to `v2.7.1` and to bridge commit `8480bdc`,
whose diff is two `docs/03_Plans/completed/*.md` paths and nothing else.

## Validation

`scripts/check_harness.py` and `scripts/check_release_preflight.py` pass, and
the provenance verifier accepts the new anchor pairing against the shipped tag.
Recorded below with real outcomes rather than asserted.

## Rollback

Revert. Nothing here is published; `v2.7.1` is already tagged and on PyPI
independently of this commit, so reverting only returns the documentation and
the anchor to their pre-close-out state.

## Decision Log

- Promotion was deliberately kept OUT of the bridge commit. The harness couples
  promotion to the anchor, and the anchor lives in `scripts/`, so promoting in
  the bridge would have dragged executable content into a commit that must
  carry none. That is the exact failure that made every release after `v2.7.0`
  unverifiable.
- The three hardcoded prior-tag literals were updated by hand this time. They
  should be derived from `PRIOR_RELEASE_TAG` instead; a stale literal is
  invisible until the next tag, which is the worst possible moment to find it.

## Open

- `stage_post_release` still opens the `.dev0` bump as the only post-tag pull
  request, so on the next release it would take the bridge slot and poison it.
  Tracked as task #38 along with the harness check that makes that loud.
