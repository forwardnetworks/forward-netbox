# Release 3.0.13

## Goal

Fix what the first customer bundle from 3.0.12 showed: a device that was another device's BGP neighbour could not be deleted, a long config backup blocked every sync and sync-form save, changing a primary-IP setting did nothing when Forward had no new data, merged routing deletes never reached the change log, and the bundle's issue and primary-IP guidance still left the operator guessing. Move the tested runtime to NetBox 4.7.4 and netbox-branching 1.2.3.

## Constraints

- No customer names, network ids, snapshot ids, hostnames or addresses in the repo, plans, tests or docs. Tests use synthetic names.
- No shipped NQE query change, so nothing to republish. No migration.
- The one new stored parameter is a plugin-owned marker, `overlay_rerun_pending`, set when a primary-IP setting changes and cleared once the step has run.
- The delete fix keeps every address and BGP peer: it only takes the address off the deleted device's interface. Nothing outside the selected devices' own addresses is touched.
- The support bundle stays name-free.
- `development/constraints-upgrade-from.txt` forward-sdk pin moves to 0.1.31 only in the release step, after the version bumps (the pre-push upgrade gate reads it).

## Touched Surfaces

- Delete: `scope_reconciliation.py`, `device_cascade_delete.py`, `views.py` (device lists, prune actions).
- Locks: `jobs.py` (config backup), `forms.py` (sync-form save guard).
- Overlay: `single_branch_executor.py`, `primary_ip.py`, `forms.py`, `model_validation.py`.
- Change log: `merge.py`, `sync_events.py` (reset NetBox's per-thread delete memory before a merge).
- Guidance: `cleanup_checklist.py`, `primary_ip_reasons.py`, `skip_reason_catalogue.py`, `sync_routing_static.py`, `sync_reporting.py`, `views.py` issue summary.
- Runtime: `scripts/tested_runtime.py`, `development/`, `tasks.py`, release and artifact validators, `constraints.txt`, `poetry.lock` (NetBox 4.7.4, netbox-branching 1.2.3).

## Approach

1. Land each fix with tests derived from the customer's symptom, reproduce the missing change-log rows with a real-branch test first, and run a code-reviewer audit on the delete and lock changes.
2. Run the full Django suite on the final tree, then `scripts/release.py 3.0.13` through the usual lineage.
3. After the tag nothing needs republishing; the customer upgrades, saves the setting and re-runs.

## Validation

- Real-branch test: a staged routing delete is in the main change log by request id (failed before the fix, 29 tests pass after).
- Real-branch test: a no-change run with a pending primary-IP setting provisions a branch, runs the step, merges and clears the marker; without the marker it stays branchless.
- `invoke ci` on NetBox 4.7.4 with netbox-branching 1.2.3 via `scripts/release.py`, including the artifact and upgrade legs.
- Not verified: search-cache job batching (deferred to a later release), the new pages in a browser, and the delete with a netbox-branching branch active in production.

## Rollback

Revert the release. Nothing is migrated. The marker is ignored by older plugins' validation only if they predate it, so roll back before changing a primary-IP setting.

## Decision Log

- The release-only sensitive-pattern feed is a GitHub secret and cannot be read locally, so the cut runs with the parity bypass.
- The search-cache job flood is NetBox 4.7 internals (one job per savepoint scope); batching it is deferred until it can be tested against the NetBox internals on 4.7.4.
- A device that is another device's BGP neighbour is kept consistent by detaching the address, not deleting the peer, matching how the plugin already models a neighbour address it cannot place on an interface.
