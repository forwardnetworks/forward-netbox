# Release 2.7.0

## Goal

Ship the four field-reported fixes from the 2.6.12 upgrade, plus support for the
customer's own lifecycle plugin at `0.6.0` and the capability it added.

## Contract

- Every ingestion can be deleted, or is told plainly what holds it.
- A primary IP moving between devices converges.
- CIMC firmware reaches device lifecycle, or no row is written.
- No existing sync path changes behaviour for an operator who enables nothing.

## Constraints

- `netbox_branching` stays in the ingestion path.
- No additional NQE call volume per sync beyond the one opt-in map.
- Persisted diagnostics stay free of customer data.
- All four version surfaces bump together.

## Touched Surfaces

- Version: `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py` runtime pin,
  `forward_netbox/tests/test_runtime_dependency_check.py`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`
- This plan. The four changes themselves each carry their own plan:
  `2026-08-01-hidden-protect-relations.md`,
  `2026-08-01-primary-ip-reassignment-root-cause.md`,
  `2026-08-01-cimc-software-lifecycle.md`,
  `2026-08-01-dlm-0.6.0-support.md`.

## Approach

Four commits on `release/2.7.0` off `2.6.12`:

1. `af0fc5b` names the ownership conflict at the shared formatter rather than at
   one call site.
2. `dd28dd6` converges owned primary-IP reassignments. This squashes an earlier
   commit that failed its own tests; that commit was never published and
   carrying it as history would have described a fix that did not work.
3. `52ade9c` accepts netbox-dlm `0.6.0` and reports CIMC firmware into it.
4. `ff81478` makes the hidden PROTECT relations visible to the ingestion delete
   refusal.

**Version surfaces bump in one change.** Bumping the fast-baseline runtime pin
separately from the version reverts the fast baseline from roughly six minutes
to roughly fifteen hours, with nothing an operator can see. They move together
or not at all.

**What is deliberately not in this release.** The merge delete-predictor shares
the hidden-relation blind spot fixed in (4). Widening it was implemented and
measured: it regressed three tests, the worst silently keeping a device that
should have been deleted, because the merge clears that reference in the same
transaction. The release notes state this limitation rather than omitting it.

## Validation

- `test_bulk_merge` + protecting-relations: 96 tests OK.
- primary-IP focused: 4 tests OK; surrounding `test_bulk_merge` + `test_sync`:
  407 tests OK.
- DLM suites with `0.6.0` installed: 79 tests OK; after the platform rename to
  `CIMC`: 31 tests OK.
- `fast_baseline_field_contract_drift()` returns `[]` against a clean runtime.
- Full local gate and exact-runtime artifact test, recorded below.

## Rollback

The four commits are independent and each reverts alone. Reverting the DLM
commit returns the version ceiling to `<0.6.0`, which refuses the customer's
installed plugin, so that one is paired with a decision rather than reverted on
its own.

## Decision Log

- 2026-08-01: Squashed the failing primary-IP commit rather than fixing forward
  on top of it. A release branch should not contain a commit whose message
  claims a fix its own tests reject.
- 2026-08-01: Platform named `CIMC`, not `Cisco CIMC`, at the plugin author's
  request. It is his data model.
- 2026-08-01: Shipped the proven half of the PROTECT-visibility fix and deferred
  the half that regressed, with the reproduction recorded.

## Open

- The merge delete-predictor blind spot.
- SNMP endpoints not covered by an import tag: diagnosed as the
  `sync_generic_endpoints` opt-in being disabled, not a defect. 421 console
  servers import by default, 179 generic need the toggle, 84 CIMC are excluded
  by design as inventory items.
