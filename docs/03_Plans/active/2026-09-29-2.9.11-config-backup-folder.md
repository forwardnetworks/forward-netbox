# Make the config backup folder configurable

## Goal

Config backup wrote every device's file to the literal folder `configs`. An
operator whose repository already has another layout - or who wants the backup
under a nested path, or to share a repository - had to reshape the repository
or go without. Add one source setting for the folder, keep the default so
nothing changes for anyone who does not set it, and make sure Health tells
Validity's operator the folder that is actually in use.

## Constraints

- One new source parameter, `config_backup_path_prefix`, default `configs`,
  relative to the repository root, nested paths allowed. It follows the
  three-places rule for a new source parameter: the form, the source validator's
  key allowlist and its value check, and the parity test that compares them.
- The folder is operator input that becomes repository structure, so the rules
  are strict and live in one stdlib-only module: no leading slash, no empty
  segment, no `.` or `..`, no backslash or control character, no `.git`, no
  first segment `unmanaged` (the fixed folder for devices this sync does not
  manage), bounded length.
- Changing the folder must never delete anything. Files already written under
  the old folder stay where they are and are no longer updated; the backup job
  says so when a `configs/` folder is still present, and the form's help text
  says so before the change is made.
- A FILE where a folder is needed stops the run. Writing a tree over it would
  delete a file nobody asked us to touch.
- The unmanaged folder stays fixed at `unmanaged`; filenames stay
  `<NetBox device name>.cfg`. No migration.
- Health and the bundle carry the folder as a boolean (`customized`, `valid`),
  never the path, in line with the value-free delivery payload.

## Touched Surfaces

- `utilities/config_backup_path.py` (new): the rules, the segments, the
  matching Validity template.
- `utilities/config_backup.py`: read and write the folder as a nested tree
  (`_entries_at`, `_replace_at`), the stale-folder warning, the file-in-the-way
  and invalid-folder failures.
- `forms.py`, `utilities/model_validation.py`: the field, its cleaning, both
  parameter builders, the allowlist and the value check.
- `utilities/health.py`: the expected Validity path follows the configured
  folder; the delivery bundle gains two booleans.
- `docs/01_User_Guide/configuration.md`.
- Tests: the rules, the source validator, the form, the nested tree against a
  local bare repository, and the Health messages.

## Approach

The backup walks the head commit's tree down the folder's segments to find the
existing files, then rebuilds each folder on the way back up with every sibling
carried over untouched, so a nested folder changes only its own files. The old
literal top-level handling becomes the one-segment case of the same code.

`ForwardSourceForm.save()` rebuilds the source parameters and had left out
`config_backup_include_unmanaged`, so that checkbox never persisted through the
GUI. It is added there with the new field, and a form round-trip test covers
both.

## Validation

- `test_config_backup_path`, `test_config_backup_folder` (nested write,
  no-change run, sibling preserved, old folder left with a warning, unmanaged
  apart, file in the way, invalid stored folder), `test_forms`,
  `test_config_backup`, `test_config_backup_job_and_health`,
  `test_source_parameter_keys_agree`.
- Full `invoke ci` before merge.

## Rollback

Revert the commit. A source that stored `config_backup_path_prefix` keeps an
unused key; the older validator would refuse it, so clear it first on a
downgrade.

## Decision Log

- **One folder setting, not a filename template.** Validity binds devices by
  name through its own template, so the extension and the device-name filename
  are the contract; the folder is the part a repository layout varies.
- **Warn about the old folder, do not move it.** Moving or deleting files in
  someone's repository is a destructive path with no allowlist to justify it.
- **The default `configs` folder is the only one the job looks for when
  warning.** A previous custom folder is unknown to the job; the form help text
  covers that case.
