# Release 3.0.9

## Goal

Ship the support-bundle follow-up to 3.0.8 (PR 584): the bundle says why each device has no primary IP without asking the customer. The management-address step records each bare device's reason as ids-only job-log lines, the "none chosen" finding carries the step's counts, and `primary_ip.management_step_outcomes` splits each reason's devices by what the step recorded.

## Constraints

- No customer names, network IDs, snapshot IDs, hostnames or addresses in the repo, plans, tests or docs. Tests use synthetic names.
- No shipped NQE query in this release, so there is nothing to republish. One migration (0067) adds four columns to the change record and a table for change-control proposals; it only adds, so an older plugin ignores it. The one runtime dependency change is forward-sdk 0.1.22 to 0.1.27 (maps support), planned in `2026-10-27-site-network-maps-panel.md`.
- The release tool lock moved `filelock` to 4.2.4 (`poetry.lock` too) and `virtualenv` to 21.14.13 because the release preflight refuses locks that carry a known advisory.
- The Python floor rises from 3.10 to 3.12 (`pyproject.toml`, the classifiers, and `poetry.lock` regenerated): NetBox 4.7 and Branching 1.2 already need 3.12, and every filelock fix needs 3.11, so the dev lock could not leave a vulnerable entry while it resolved for 3.10. The package's `Requires-Python` metadata changes with it; nothing that ran on 3.10 or 3.11 could run the plugin anyway.
- No Dependabot alert is waived: the virtualenv, filelock and msgpack alerts closed once their fixed pins reached main (PRs 586 and 588), so `ACCEPTED_DEPENDABOT_ALERTS` is empty again.
- The upgrade gate's from-side pin `forward-sdk` in `development/constraints-upgrade-from.txt` moves to 0.1.22 because the previous release (3.0.8) ships that pin; the first cut attempt failed there.
- Explanatory text reports what the step recorded and nothing about what a sync will do; the classifier is unchanged after review rejected a broader "shared" rule.

## Touched Surfaces

- `forward_netbox/utilities/` primary_ip, primary_ip_reasons, explained_findings; `forward_netbox/views.py` (bundle payload).
- `forward_netbox/utilities/network_maps.py`, the Site Network Maps panel and forward-sdk 0.1.27 (see `2026-10-27-site-network-maps-panel.md`).
- Change-control Predict scaffold (see `2026-10-27-change-control-predict-scaffold.md`): `forward_netbox/change_control/predict.py`, `workspace.py`, `actions.py`, `signals.py`, migration `0067_change_proposal.py`, the change page, REST actions. Advisory only; not verified against a live Forward.
- `requirements-release.txt`, `poetry.lock`, `scripts/check_release_preflight.py` (the waiver list) and the release surfaces written by `scripts/release.py`.

## Approach

1. PR 584 merged to `main` after the full pre-push gate passed on its tip.
2. Run `scripts/release.py 3.0.9` through the usual lineage: cut, authorize, evidence, tag, post-release bridge, anchor.
3. After the tag nothing needs republishing. A customer upgrades and re-syncs; the next bundle carries the per-device reasons. A bundle from a sync that ran on 3.0.8 reports `device_lines_present: false`.

## Validation

- `invoke ci` on the pushed tip of PR 584 (passed, including the artifact upgrade test) and again on the release tree via `scripts/release.py`.
- `pre-commit run --all-files`, `invoke harness-check` and 122 targeted tests, including integration tests that run the step against a real branch.
- Not verified: the per-device lines against a customer-scale estate (about 130 extra log lines at 20,000 bare devices, estimated, not measured).

## Rollback

Revert the release. The job-log lines are additive; an older plugin ignores them.

## Decision Log

- Parsing the lines back from the job log needs no migration; a marker line is always written so an older log is not read as "recorded nothing".
- The release-only sensitive-pattern feed is a GitHub secret and cannot be read locally, so the cut runs with the parity bypass; the release workflow runs the real feed at tag time.

## Cut-time steps that are not in this feature branch

- `development/constraints-upgrade-from.txt` moves forward-sdk 0.1.20 to 0.1.22 in the release commit (3.0.8 pins 0.1.22); on a 3.0.8-versioned tree the upgrade test starts from 3.0.7, which needs 0.1.20.
- The version strings, the README row and the CHANGELOG line are written by `scripts/release.py 3.0.9 --summary ... --write`.
