# Release 2.9.10

## Goal

Cut `2.9.10` on the `maint/2.9.x` lane. A customer's 2.9.9 upgrade showed
four problems, all of which failed without saying so: every in-scope device
was called out of scope, the repair for their 221 duplicate device pairs
merged nothing, config backup failed with an unexplained protocol error, and
every first sync ran on the slow path. Ship the fixes, and the prompts that
make the same class of problem visible, then record the release note for the
six commits merged since `v2.9.9`.

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `2.9.10` together, or `check_harness.py`
  refuses the release.
- The tested runtime is unchanged at NetBox `4.6.10`.
- No code change in this commit: every functional change already landed as
  its own reviewed, `invoke ci`-green PR.
- No `@query` parameter list changed, so nothing in a customer's published
  queries breaks. The three routing-policy maps gained an output column
  (`scope_holders`); Publish Bundled Queries picks it up, and a stale
  published copy keeps its previous behaviour. `check_bundled_query_signatures`
  passes on the real tree.
- No migration.
- No customer names, identifiers, or scan-matching hostnames in this plan,
  the changelog entry, or the release commit message.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,

## Approach

`scripts/release.py 2.9.10 --write --summary "..."` bumps every version
surface and the fast-baseline pin in the same commit and regenerates
`CHANGELOG.md` from the README compatibility table. The six commits it covers
(oldest to newest):

1. **Scope by name, relabel pairs by the device map's site** (#476). Fixes
   2.9.9's site test, which compared a slug derived from Forward's location
   to NetBox's site slug and matched none of a real estate's sites. Forward's
   site for duplicated names now comes from the sync's own device map, so the
   repair proves pairs by it and keeps the older device at that site.
2. **Site-relabel duplicates are never silent** (#477). A Health check, a
   sync-page banner, a card on Scope Reconciliation, a hint on the blocked
   primary-IP issue, and a post-sync log line.
3. **Config backup reaches the repository the way NetBox does** (#478). NetBox's
   proxy, credentials as transport arguments (the URL used to reach the worker
   log), rejected branches fail, and failures name a closed cause in the job,
   Health and the support bundle.
4. **The fast paths run on any subset of the validated plugins** (#479). An
   absent optional plugin no longer disables the fast baseline, COPY/SQL or
   the set-based merge; an extra plugin still does. The absent-plugin
   hazards that the old rule masked are fixed in the same change.
5. **Routing policy scope by every holder, pending removals as staged**
   (#480). Live-validated against the customer's network. Pending removals
   were counting rows the durable state had already applied.
6. **Operator cleanup for routing policy no in-scope device holds** (#481).
   Allowlisted, gated like the prunes, and limited to entries this sync
   provably created.

## Rollback

This commit is a version bump and changelog entry only. Reverting it restores
the previous version surfaces; the functional PRs need their own reverts. No
migration ships in this release.

## Decision Log

- **Released as one batch of six.** The scope regression and the repair that
  could not act are one customer-facing problem, and the prompts, the
  config-backup and fast-path fixes came from the same support bundle.
  Splitting them would have made the customer upgrade repeatedly for one
  incident.
- **Not held for the 3.0.1 port.** The 4.7 lane has not shipped 2.9.7 or
  later; it follows this release and carries every fix in it.
