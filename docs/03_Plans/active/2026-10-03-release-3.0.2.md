# Release 3.0.2

## Goal

Cut `3.0.2` on `main` (the NetBox 4.7 lane). Carries forward everything the
4.6 lane has that this lane did not yet have: `#510` (the missing
`UPGRADE_FROM_NETBOX_OVERRIDES` entry for `3.0.1`, already merged) and `#516`
(port of `maint/2.9.x`'s v2.9.13 fix `#511` - the site-relabel duplicate
repair's bare `ProtectedError` crash on a `PeeringSession`-protected
`BGPPeer`, and SNMP endpoint IPv4 addresses always syncing as /32).

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `3.0.2` together.
- The tested runtime is unchanged at NetBox `4.7.1` / `netbox-branching`
  `1.2.0`.
- `UPGRADE_FROM_NETBOX_OVERRIDES` needs a `3.0.2`-side check: the auto-detected
  from-release will be `3.0.1`, which already carries its own override
  (`v4.7.0`) from `#510` - no new override entry is needed for this cut, only
  verification that the existing one still resolves correctly.
- No code change in this commit: both functional changes already landed as
  `#510` and `#516`, each reviewed and gated on its own branch.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`.
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`,
  `CHANGELOG.md`.
- This plan.

## Approach

`scripts/release.py 3.0.2 --write` bumps every version surface and the
fast-baseline pin in the same commit and regenerates `CHANGELOG.md` from the
README compatibility table. The commits it covers:

- **`#510`.** `UPGRADE_FROM_NETBOX_OVERRIDES["3.0.1"] = "v4.7.0"` - without
  it, `artifact-upgrade-test` auto-detects the from-side as `3.0.1` and
  silently seeds on the default `v4.6.5` runtime, which is below this
  plugin's own `4.7.0` minimum and fails plugin load entirely. This was
  caught live by the 3.0.2 gate itself before this cut.
- **`#516`.** The same two fixes `#511` shipped on `maint/2.9.x` as v2.9.13,
  cherry-picked onto `main` with no conflicts (neither touched file had
  diverged between lanes): the recursive allowlisted-blocker release in
  site-relabel repair, and the SNMP netmask-to-prefix-length lookup for
  endpoint IPv4 addresses.

## Validation

- `#510`'s and `#516`'s own `invoke ci` pre-push gates both passed before
  merge (118 tests for `#516` specifically, full suite for both).
- `#516`'s own gate on `main` included the artifact-upgrade-test leg: `3.0.0`
  on NetBox `v4.7.0` -> `3.0.1` on NetBox `v4.7.1`, rows surviving.
- `scripts/release.py 3.0.2 --write` verify step: version-surface
  consistency, UI harness dependencies, advisories, Dependabot alerts,
  `poetry.lock` parity, `check_bundled_query_signatures`, `check_harness.py`,
  full `invoke ci` and `invoke artifact-test`, including an
  artifact-upgrade-test leg that will now correctly seed the from-side
  (`3.0.1`) on NetBox `4.7.0` via `#510`'s override entry.

## Rollback

This commit is a version bump and changelog entry only. Reverting it
restores the previous version surfaces; `#510` and `#516` each need their own
revert. Neither carries a migration.

## Decision Log

- **Discarded a stale, stashed release-prep draft** from before `#510`/`#516`
  merged rather than reconciling it: the changelog/README text it carried
  predated both fixes and would have needed a full rewrite anyway, and
  those files are machine-generated by `scripts/release.py` from the README
  table, not hand-maintained.
- **No new `UPGRADE_FROM_NETBOX_OVERRIDES` entry for this release** - the
  existing `3.0.1` entry already covers the from-side this cut's upgrade
  test will auto-detect.
