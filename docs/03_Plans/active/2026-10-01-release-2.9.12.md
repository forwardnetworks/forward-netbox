# Release 2.9.12

## Goal

Cut `2.9.12` on the `maint/2.9.x` lane. Ships the config-backup parsed-tree
fallback (`#500`) and the 2.9.12 tranche (`#504`): a stuck-sync close-out, a
site-relabel duplicate repair that was merging nothing, primary-IP coverage for
SNMP endpoints and untagged devices, BGP peer policy links, and a new opt-in
static-route map, all raised by one customer's estate.

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `2.9.12` together, or `check_harness.py`
  refuses the release.
- The tested runtime is unchanged at NetBox `4.6.10`.
- No code change in this commit: the functional changes already landed as
  `#500` and `#504`, each reviewed and gated on its own branch.
- The temporary Dependabot waiver `#504` added must still name every id it
  accepts; it is not removed here, since the alerts have not yet re-scanned
  the merged lock.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`.
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`,
  `CHANGELOG.md`.
- This plan.

## Approach

`scripts/release.py 2.9.12 --write` bumps every version surface and the
fast-baseline pin in the same commit and regenerates `CHANGELOG.md` from the
README compatibility table. The one commit it covers contains two merged PRs:

1. **Config backup parsed-tree fallback (`#500`).** The config backup query
   falls back to `device.files.config` when a device has no collected `CONFIG`
   command, and also emits endpoint CLI output that is a configuration. Live:
   3,509 files for 3,555 in-scope devices on one estate, up from 2,743.
2. **The 2.9.12 tranche (`#504`):**
   - A sync stuck at "Ready to merge" after its branch merge applied can now be
     closed out; an empty stuck-sync verdict says why, and the merge evidence
     is in the support bundle.
   - The site-relabel duplicate repair released the sync's own routing rows
     that blocked deleting the newer copy of a pair, instead of merging none
     of them; the last run's outcome shows on the Scope Reconciliation page.
   - Deleting a sync waits two minutes on the ownership lock before naming the
     holding session, and the confirmation lists the tags it would strip with
     an option to keep them. Module Readiness runs as a background job.
   - SNMP endpoints and same-name duplicate devices now resolve a primary IP
     from their `Mgmt_` tag; a new opt-in setting falls back to Forward's
     single management address for a device with none. The bundle reports
     coverage.
   - BGP peer address families link to their route maps and prefix lists, read
     from device configuration.
   - A new opt-in map syncs configured static routes into `netbox-routing`.
   - `poetry.lock` moves past six Dependabot alerts (Django, urllib3,
     virtualenv), with a temporary waiver in `check_release_preflight.py`
     naming each id until the alerts re-scan.

## Validation

- `invoke ci` passed on `#504`'s branch before merge: 3,321 Django tests, 422
  scripts tests, pre-commit, and the UI and upgrade legs.
- `scripts/release.py 2.9.12 --write` verify step: version-surface
  consistency, UI harness dependencies, advisories, Dependabot alerts,
  `poetry.lock` parity, `check_bundled_query_signatures`, `check_harness.py`,
  full `invoke ci` and `invoke artifact-test`.
- The peer address-family and route-map queries, and the static-route query,
  were run against a real network (not a test fixture): the same address-family
  rows as before plus the new policy columns (290 attachments, all resolving to
  an imported policy); every configured static-route line on the network
  parses. The primary-IP resolver was replayed against the same real device,
  endpoint and interface data: 3,676 of 4,035 tag-eligible endpoints/devices
  resolve, and the new management-IP fallback recovers 758 more untagged
  devices.
- Not exercised on a live Forward sync or a customer's NetBox: the
  static-route and primary-IP apply paths, and the delete confirmation in a
  browser, have unit and integration tests only.
- The sensitive-pattern parity check runs UNVERIFIED in this checkout
  (`FORWARD_SENSITIVE_PATTERNS` is a CI-only secret); the release gate applies
  the superset feed and can still refuse the tag.

## Rollback

This commit is a version bump and changelog entry only. Reverting it restores
the previous version surfaces; `#500` and `#504` need their own reverts.
Migration `0058` only widens the NQE map model choices and leaves no orphaned
data if reverted; any `StaticRoute` rows the opt-in map created stay in NetBox
and carry the sync's own marker.

## Decision Log

- **Released as one version**, not split, because `#500` was already staged
  and ready and `#504` was the customer-facing work the same estate raised;
  splitting them would have shipped the fix for 310 of 562 uncovered devices a
  release later than necessary.
- **Static routes and the primary-IP fallback ship opt-in** (off by default)
  because their apply paths have no live acceptance run yet.
- **The Dependabot waiver is not removed in this commit.** It names the
  specific ids the merged lock fixes; removing it is a follow-up once GitHub
  re-scans and the alerts close, not a condition of this release.
- **Not held for the 4.7 line.** The same change ports to `main` after this one
  ships.
