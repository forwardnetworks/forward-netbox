# Release 2.9.14

## Goal

Cut `2.9.14` on `maint/2.9.x`. It carries three changes landed after 2.9.13,
all found while a customer ran 2.9.13 against a large real estate: global-table
static routes now apply (`#521`), the 4.6 lane's optional plugins move to their
latest releases (`#522`), and three follow-ups to the duplicate repair and the
primary-IP step (`#523`).

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `2.9.14` together, or `check_harness.py`
  refuses the release.
- The tested runtime is unchanged at NetBox `4.6.10`.
- No code change in this commit: every functional change already landed as
  `#521`, `#522` and `#523`, each gated on its own branch.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`.
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`,
  `CHANGELOG.md`.
- This plan.

## Approach

`scripts/release.py 2.9.14 --write` bumps every version surface and the
fast-baseline pin in one commit and regenerates `CHANGELOG.md` from the README
compatibility table. The commits it covers:

- **`#521`.** A configured static route outside any VRF carries a null `vrf`,
  and fetch-time validation refused a null `vrf` for every model except
  `ipam.prefix`, so the whole static-route model was skipped on every run. The
  refusal is now named instead of reading as an unrecognized failure, the
  adapter readiness check no longer reports working adapters as missing, and
  `scrapli` is pinned because a release published on 2026-10-03 stopped NetBox
  booting on a fresh image build through `netbox-validity`.
- **`#522`.** `netbox-peering-manager` 0.3.1, `netbox-validity` 3.6.0 and
  `netbox-routing` 0.5.0, each declaring a NetBox range that includes 4.6.
- **`#523`.** `BGPAddressFamily` joins the rows the duplicate merge may release,
  the management-address fallback now covers devices whose `Mgmt_` tag
  resolved nothing and the sync log says why other devices have no primary IP,
  and the Site-Relabel card names the held devices.

## Validation

- `#521`, `#522` and `#523` each passed the full `invoke ci` pre-push gate.
- `scripts/release.py 2.9.14 --write` verify step: version-surface consistency,
  advisories, Dependabot alerts, `poetry.lock` parity,
  `check_bundled_query_signatures`, `check_harness.py`, full `invoke ci` and
  `invoke artifact-test`.
- The sensitive-pattern parity check runs UNVERIFIED in this checkout
  (`FORWARD_NETBOX_PATTERN_PARITY_UNVERIFIED` is set); the release gate applies
  the superset feed and can still refuse the tag.

## Rollback

This commit is a version bump and changelog entry only. Reverting it restores
the previous version surfaces; each of `#521`, `#522` and `#523` needs its own
revert. None carries a migration.

## Decision Log

- **Released promptly as a patch** because the customer's static routes were
  skipped entirely and the duplicate repair still left pairs behind.
- **Orgs with pinned query copies must republish.** The static-route query is
  new in 2.9.12 and an org-backed deployment needs Publish Bundled Queries.
