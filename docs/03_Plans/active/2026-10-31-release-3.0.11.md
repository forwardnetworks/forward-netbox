# Release 3.0.11

## Goal

Ship the recovery tranche that follows 3.0.10 (PR 605): a failed sync explains itself on screen, a query Forward fails internally is retried, and the Forward device lists paginate and let an operator act on what they show. The customer who reported the failed sync can read the blocking reasons and what to do without a command line, and can delete devices that netbox-routing records were blocking.

## Constraints

- No customer names, network ids, snapshot ids, hostnames or addresses in the repo, plans, tests or docs. Tests use synthetic names.
- No shipped NQE query change, so nothing to republish. No migration.
- The one runtime dependency change is forward-sdk 0.1.27 to 0.1.29 (opt-in NQE outcome retries). The upgrade gate's from-side pin in `development/constraints-upgrade-from.txt` stays at 0.1.27 because the previous release (3.0.10) ships that pin.
- The delete path removes only routing rows that hang off the devices being deleted and no other; anything else that blocks a device refuses and restores everything.
- The support bundle stays name-free.

## Touched Surfaces

- NQE fetch: `forward_api_impl.py`, `forward_client_errors.py`, `diagnostics.py`, `forward_usage.py` (retry on a system-error outcome, outcome slugs).
- Blocked syncs: `single_branch_executor.py`, `validation.py`, `validation_guidance.py`, `sync_orchestration.py`, the validation run page, bundle fields for the blocking reasons.
- Device lists and bulk actions: `views.py`, `urls.py`, `device_cascade_delete.py`, `scope_reconciliation.py`, the device list and delete templates.
- Wording and reconciliation on Scope Reconciliation, Health and Explained; `bundle_label_index.py`.
- `constraints.txt`, `pyproject.toml`, `poetry.lock`, `scripts/validate_sbom.py` (forward-sdk 0.1.29) and the release surfaces written by `scripts/release.py`.

## Approach

1. PR 605 merged to `main` after two code-reviewer audits, with every finding fixed and tested, and the full Django suite passed on the merged tree (4199 tests, 33 skipped).
2. Run `scripts/release.py 3.0.11` through the usual lineage: cut, authorize, evidence, tag, post-release bridge, anchor.
3. After the tag nothing needs republishing. A customer upgrades and re-syncs.

## Validation

- `invoke ci` on the release tree via `scripts/release.py`, including the artifact and upgrade legs.
- The full Django suite on `main` at the last merge: 4199 tests OK. Scripts tests: 461 OK.
- `pre-commit run --all-files` and `invoke harness-check`.
- Not verified: the retry against a live Forward failure (none can be provoked on demand), the new bulk pages in a browser, and a device delete with a netbox-branching branch active.

## Rollback

Revert the release. Nothing is migrated; the new bundle fields are additive and an older plugin ignores them.

## Decision Log

- The release-only sensitive-pattern feed is a GitHub secret and cannot be read locally, so the cut runs with the parity bypass; the release workflow runs the real feed at tag time.
- The routing cascade is opt-in on the confirmation page; unticked, the delete is NetBox's own.
