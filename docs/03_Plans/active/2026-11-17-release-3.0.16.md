# Release 3.0.16

## Goal

Answer the questions a customer's latest bundles left open, and make grouping
Forward locations into NetBox sites safe:

- A completed run says which models it changed. A merged run's branch is gone, so
  the change explainer said `branch_missing` for every completed run; the counts now
  come from NetBox's change log under the run's request id.
- A verified delete of unmanaged devices that holds devices back says which device is
  held by what, the confirmation page offers to delete the routing records that hold
  them, and Scope Reconciliation shows the last result and the next step. The bundle
  covers the same, and its delete-blocker survey now includes this list.
- A device tagged `NetBox_Site_<name>` is placed at the site `<name>`; untagged devices
  keep their Forward location. One shared rule in the shipped NQE and the plugin.
- A device that moves site gets the new site's VLANs on its interfaces in the same
  run, the sync never renames a site it matches, never deletes a site that something
  still references (NetBox would cascade into prefixes and clusters scoped to it), and
  does not delete a site NetBox's change log shows another actor created.

## Constraints

- No customer names, network ids, snapshot ids, hostnames or addresses in the repo.
- No migration.
- Shipped queries changed (`netbox_utilities`, `forward_devices`,
  `forward_devices_with_netbox_aliases`, `forward_vlans`, `forward_locations`):
  customers republish them. With no site tags, the new queries return the same rows
  as before (verified live).
- `development/constraints-upgrade-from.txt` forward-sdk pin moves 0.1.35 -> 0.1.36
  in this cut (3.0.15's own pin).

## Approach

   and the combined tree had a release audit.

## Notes for the release notes

- Republish the queries first, then apply any `NetBox_Site_` tags.
- Tagging moves every tagged device in one run, and re-applies each moved device's
  interfaces: preview the run and check the branch budget before a customer tags a
  large data centre.
- The "another actor created it" guard rests on NetBox's change log: it stops
  protecting a site once its create record ages out of retention, and Prune orphans
  does not use it.
- An interface map that reads Forward's own snapshot diff does not re-apply a moved
  device's interfaces; run that sync once with a full fetch after a move.

- A site that something still references produces a skip warning on every run, until
  whatever references it is removed or moved.
- Deleting a site removes its many-to-many links (for example a config context or a
  change-validation policy scoped only to that site would then apply everywhere),
  and generic links such as contacts and journal entries. The delete check covers
  what NetBox would cascade into through a foreign key, not these.

## Cut Record

- Tranche merged to `main` as PR #636 (squash `43f251cc`).
- The release-time sensitive-pattern feed is a CI secret and cannot be read locally,
  so the cut ran with the unverified-parity flag; the publish workflow applies the
  superset feed and can still refuse the tag.

## Rollback

Revert the release and republish the 3.0.15 queries. Nothing is migrated.

## Decision Log

- Site grouping is a device tag, not a per-customer rule in the queries: a rule in one
  customer's copy of the queries reached only some of the maps that name a site.
- A site's name and slug are create-only: another system that owns a site would
  otherwise be renamed back and forth on every run.
