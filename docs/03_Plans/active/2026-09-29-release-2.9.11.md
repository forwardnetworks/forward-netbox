# Release 2.9.11

## Goal

Cut `2.9.11` on the `maint/2.9.x` lane. A customer's 2.9.10 upgrade produced a
first run of about 147,000 changes that merged automatically before anyone
could ask whether it was right, and a config backup that produced fewer files
than there are devices with no way to see why. Ship the guard and the
evidence that make both visible, plus a configurable config backup folder, and
record the release note for the change merged since `v2.9.10`.

## Constraints

- Version surfaces (`pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`, the README
  compatibility tables) must all read `2.9.11` together, or `check_harness.py`
  refuses the release.
- The tested runtime is unchanged at NetBox `4.6.10`.
- No code change in this commit: the functional change already landed as its
  own reviewed, `invoke ci`-green PR.
- No `@query` parameter list changed and no bundled query changed, so nothing
  in a customer's published queries needs republishing.
- No migration.
- No customer names, identifiers, or scan-matching hostnames in this plan,
  the changelog entry, or the release commit message.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,

  `forward_netbox/tests/test_runtime_dependency_check.py`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`,
  `CHANGELOG.md`
- this plan

## Approach

`scripts/release.py 2.9.11 --write --summary "..."` bumps every version
surface and the fast-baseline pin in the same commit and regenerates
`CHANGELOG.md` from the README compatibility table. The one commit it covers
is #490, which contains:

1. **Auto merge review hold.** With Auto merge on, after the sync has finished
   a run before, a model that stages at least 10,000 changes at 3x its table's
   established size (or 10x the median of earlier runs) stops the run for
   review. It fails open; a held run stays staged.
2. **Evidence in Health and the support bundle.** Forward's row count next to
   NetBox's per model, the last three ingestions with job and merge status,
   statistics and merged changes over every change, a BGP peer duplicate
   count, and plain-words flags for an abnormal run, a baseline that never
   completed and a NetBox table far smaller than Forward's.
3. **Configurable config backup folder** and a config backup result that
   reports rows, written, unchanged, unmapped, managed devices with no
   collected configuration and files in the folder.
4. **Two fixes:** the bundle's empty merge job for an Auto merge, and the
   Include unmanaged configuration checkbox that never persisted.

## Rollback

This commit is a version bump and changelog entry only. Reverting it restores
the previous version surfaces; the functional PR needs its own revert. No
migration ships in this release.

## Decision Log

- **Released as one change.** The guard and the evidence come from one
  incident and only make sense together: the guard stops the run, the evidence
  says why.
- **The hold's norm is the table's own size, not the learned change density.**
  Density is changes per written row and cannot say how many rows a run
  writes.
- **Not held for the 4.7 line.** The same change ports to the next release on
  `main` after this one ships.
