# Port the 2.9.11 tranche onto main

## Goal

`2.9.11` shipped on the 4.6 line with a review hold for Auto merge, run-size
and row-count evidence in Health and the support bundle, a configurable config
backup folder and a config backup result that explains a gap between files and
devices. `main`, the 4.7 line, has none of it, so a deployment moving to 4.7
loses the guard that would have stopped a 147,000-change first run from
merging unreviewed. Bring the tranche across as one change so `3.0.1` ships
it.

## Constraints

- **One change, not a replay.** The 2.9.11 change is one squashed commit
  (`3c337f71`) on top of `2.9.10`, and `main` already carries everything
  through `2.9.10`, so the change applies as one three-way merge.
- **`main`'s own work wins where the lines overlap.** The release, version and
  packaging files are untouched. `enable_predict`, which only `main` has,
  stays beside `config_backup_path_prefix` in the source form, its validator
  allowlist and its type check.
- **The forward-sdk client has no public methods.** Anything that called a
  `ForwardClient` method goes through the free function instead, and tests
  that stubbed the method stub the free function.
- No migration, no `@query` change, no version bump. Version surfaces and
  README rows come with the `3.0.1` release commit.
- No customer names, identifiers, or scan-matching hostnames.

## Touched Surfaces

- New modules: `utilities/health_evidence.py`, `run_size_anomaly.py`,
  `run_size_guard.py`, `config_backup_path.py`.
- Changed: `utilities/health.py`, `change_explainability.py`,
  `config_backup.py`, `single_branch_executor.py`, `model_validation.py`,
  `forms.py`, `views.py`, the Health template, `docs/01_User_Guide/`.
- Tests: the tranche's own, adapted where they stubbed a removed client
  method (`get_networks`, `run_nqe_query`).
- `.pre-commit-config.yaml`: the new docstring-first modules and tests join
  the exclude list.
- The four `2.9.11` plan docs travel with the code they describe.

## Approach

`git cherry-pick -n 3c337f71` onto `origin/main`, then resolve four conflicts:

1. `forms.py`, `model_validation.py`: keep `enable_predict` and add
   `config_backup_path_prefix` beside it at every site (field, initial,
   fieldsets, cleaned dict, allowlist, type check).
2. `config_backup.py`: keep `main`'s `run_nqe_query` import and add the path
   helpers.
3. `.pre-commit-config.yaml`: union of the exclude entries.

Then adapt the tests: `ForwardClient.get_networks` becomes
`forward_netbox.models.get_networks`, and the config backup fake client is
adapted to the `run_nqe_query(client, ...)` free function the way the existing
config backup tests do.

## Validation

- Every new module and entry point from the tranche is present on this tree.
- Pre-commit twice, the scripts suite, the harness check.
- The new and changed Django tests, one at a time on the isolated test stack.
- Full `invoke ci`, including the upgrade legs, before merge.
- Not exercised against a live Forward or a customer estate; the Health
  evidence and the hold are unproven at that scale, in particular the time
  limit on a table of about 144,000 rows.

## Rollback

Revert the commit. No migration or data change, so the previous behaviour
returns and files a config backup already wrote stay in their repository.

## Decision Log

- **Cherry-pick over a merge.** The tranche is one commit, so a three-way
  apply against `main` is the whole job and keeps `main`'s history linear.
- **Tests adapted, not the code.** The differences are all in how a test
  reaches the SDK, so the production code is the 2.9.11 code unchanged.
- **The hold's norm stays the table's size and earlier runs**, not the learned
  change density, for the reason the 2.9.11 plan records.
