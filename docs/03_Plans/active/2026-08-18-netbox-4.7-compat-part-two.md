# NetBox 4.7 compatibility, part two: stop depending on nested groups

## Goal

Remove the plugin's remaining ties to the nested-group implementation NetBox
4.7 replaces, and say what an operator planning that upgrade has to check.

## Why

Part one made the merge's tree detector prove itself. The compatibility scan
listed three more items; measuring them settled two immediately and left one
real change.

**The serializers.** All eight Forward API serializers inherited
`NestedGroupModelSerializer`. Its only addition over
`OrganizationalModelSerializer` is

    _depth = serializers.IntegerField(source='level', read_only=True)

None of these models have a `level` field and none are hierarchical, so the
base class was inaccurate from the start. It was harmless only because `_depth`
was never listed in any `Meta.fields` - a thin reason for a declaration to be
wrong, and no reason at all once 4.7 swaps django-mptt for ltree behind that
class.

**The `querystring` template tag.** Nothing to do: the repository contains no
use of it, in templates or Python. Closed by measurement rather than carried as
a task.

**PostgreSQL 15+ and Redis 6+.** These are NetBox 4.7's own service minimums,
not the plugin's, and they are the part of that upgrade that installing a newer
plugin does not fix. Documented as NetBox's requirement, not claimed as ours.

## Constraints

- No rendered API field may change. This is a base-class correction, not an API
  change, and it must be provable rather than asserted.
- Do not raise `max_version`. The plugin refuses to load on 4.7 today, and that
  claim can only change after a gate has actually run on a 4.7 runtime.
- Do not invent 4.7 symbols. Nothing here names a class or field that has not
  been read off the installed NetBox.

## Touched Surfaces

- `forward_netbox/api/serializers.py` - one import, eight base classes
- `forward_netbox/tests/test_api_serializer_base.py` (new)
- `docs/01_User_Guide/README.md` - requirements, refreshed and extended
- `.pre-commit-config.yaml`

## Approach

`OrganizationalModelSerializer` is the same class minus `_depth`: it keeps
`OwnerMixin` and `NetBoxModelSerializer` in the same order. Read off the
installed NetBox rather than assumed:

    class NestedGroupModelSerializer(OwnerMixin, NetBoxModelSerializer):
        _depth = serializers.IntegerField(source='level', read_only=True)

    class OrganizationalModelSerializer(OwnerMixin, NetBoxModelSerializer):
        pass

The requirements section was also stale - it named NetBox 4.6.5 and branching
1.1.1 while the gate had moved to 4.6.8 and 1.1.2 - so it is corrected in the
same pass.

## Validation

`forward_netbox/tests/test_api_serializer_base.py` asserts the module no longer
imports the nested-group base, that no serializer has it in its MRO, and that
no serializer enumerates `_depth` or uses `fields = "__all__"` (which would let
an inherited field appear unnoticed).

`forward_netbox/tests/test_api_views.py` - 26 tests, exercising the rendered
responses - passes unchanged, which is the evidence that no field moved.

## Rollback

Revert. The serializers resume declaring themselves nested groups, which is
inaccurate today and breaks on 4.7.

## Decision Log

- **`OrganizationalModelSerializer`, not `NetBoxModelSerializer`.** The latter
  would also drop `OwnerMixin`, which is a behaviour change smuggled into a
  compatibility fix. The former differs by exactly the field that was wrong.
- **Close the `querystring` item by measuring instead of carrying it.** A task
  list that keeps an item nobody has checked is indistinguishable from one that
  keeps an item that is real.
- **Leave `max_version` alone.** Raising it is a claim about a runtime nothing
  has run on. It lifts when a gate says so.

## Open

- Whether the plugin actually works on 4.7. Unknown, and the point of the next
  step: run the suite against `v4.7.0-beta1` with the cap temporarily lifted,
  as a measurement rather than a release claim.
