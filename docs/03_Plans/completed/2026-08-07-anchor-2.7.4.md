# Advance the release provenance anchor to 2.7.4

## Goal

Point the provenance anchor at the shipped release and its post-release bridge,
and promote 2.7.4 to current in the release tables.

## Contract

- The anchor and the README table move together. The harness fails when the
  anchor names a release the table does not call current, which is what stops
  either drifting alone.
- `PRIOR_POST_RELEASE_DOC_COMMIT` must be the first first-parent commit after
  the tag, and that commit must be documentation-only.

## Constraints

- The prior-release tag is hardcoded in five coupled places now:
  `PRIOR_RELEASE_TAG` and `PRIOR_POST_RELEASE_DOC_COMMIT` in
  `verify_release_provenance.py`, the tag fetch in `release.yml`, one assertion
  in `check_harness.py`, and one in `scripts/tests/test_tasks.py`. It was six
  before the CI workflows were removed.
- `check_harness.py` reads the real workflow, so it can pass while the
  fixture-based test fails. Only `python3 -m unittest discover -s scripts/tests`
  catches that pair.
- The current-release marker is matched by regex as `| Current release;` -
  exactly that wording, with the semicolon. "Current release." silently matches
  nothing and reports zero current releases.

## Touched Surfaces

- `scripts/verify_release_provenance.py`, `scripts/check_harness.py`,
  `scripts/tests/test_tasks.py`, `.github/workflows/release.yml`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`

## Approach

Anchor `PRIOR_RELEASE_TAG` at `v2.7.4` and `PRIOR_POST_RELEASE_DOC_COMMIT` at
`3e8990e`, the archive-only bridge merged directly after the tag. Promote
`v2.7.4` to current in all three tables, mark `v2.7.2` superseded, and
regenerate the changelog from the table rather than editing it.

## Validation

`scripts/check_harness.py` and `python3 -m unittest discover -s scripts/tests`,
then `verify_release_provenance.py --tag v2.7.4` against the live repository
once this is on `main`.

## Rollback

Revert. The anchor returns to `v2.7.2`, which no longer matches the table, so
the harness fails until it is re-advanced - deliberately, since a stale anchor
is not self-announcing.

## Decision Log

- **Re-verify after re-anchoring rather than assuming.** Re-anchoring is not
  self-validating: the verifier reads the anchor it was just given, so a wrong
  commit can be accepted by the very check meant to catch it. The tag is
  verified again after this lands.

## Open

- `main` now declares `2.7.4` while post-release commits accumulate, which is
  the accepted cost of not opening a `.devN`. The next release bumps the four
  version surfaces as its first act.
