# Release 2.7.6

## Goal

Put a version number on the tranche that has accumulated since 2.7.5 - four
correctness fixes and the diagnosability work - so the customer stops running
unreleased `main`.

## Contract

- The four version surfaces move in ONE commit. Splitting them reverts the fast
  baseline from minutes to hours with nothing reported.
- The release commit carries its own release-authorization section, whose
  evidence base commit equals the parent of the commit that gets tagged. Never
  write that heading's text earlier in the plan: the checker splits on its first
  occurrence and would read the wrong section.
- The table marks 2.7.6 a RELEASE CANDIDATE, not current. The anchor and the
  "Current release" marker move together after the tag; promoting it here fails
  the harness, because the anchor still names 2.7.5.
- The tag is created locally, provenance verified, and only then pushed.
- The first first-parent commit after the tag is documentation-only.
- No `.devN` is opened on `main` afterwards.

## Constraints

- Gates run locally; there is no CI. Run the FULL plugin suite, not the suites
  that look adjacent - that is how a red test reached `main` after #153.
- Verify `invoke lint` IMMEDIATELY before each commit and again after. A pass
  from earlier in the session says nothing about the tree being committed; that
  left `main` red twice.
- PyPI egress on this host stalls on large HTTP/1.1 responses - `gh` over HTTP/2
  fetches the same payload in 0.4s while `urllib` times out past ~20KB. The
  upgrade gate needs `FORWARD_NETBOX_UPGRADE_FROM_VERSION=2.7.5`; only the
  DISCOVERY is offline, the upgrade itself runs in full.
- Disarm auto-merge before touching branch protections. An armed auto-merge
  merged a release branch as last pushed rather than as it stood, and cost a
  correction PR on 2.7.4.

## Touched Surfaces

- `pyproject.toml`, `forward_netbox/__init__.py`,
  `forward_netbox/utilities/fast_baseline.py`,
  `forward_netbox/tests/test_runtime_dependency_check.py`
- `README.md`, `docs/README.md`, `docs/01_User_Guide/README.md`, `CHANGELOG.md`

## Approach

Everything in this release is already on `main` and already ran the full plugin
suite: #161, #162, #163, #164, #167, #168. This change is the version bump and
the release notes.

## Validation

`invoke ci` and `invoke artifact-test` on the pinned environment, then the tag,
then `verify_release_provenance.py` against the local tag before pushing it.

## Rollback

Before the tag is pushed, revert the branch. After it is pushed the tag is
immutable and a defect costs a version number - which is what 2.7.3 cost.

## Decision Log

- **Prepared, not published.** The standing instruction is not to release yet.
  The branch and its evidence are ready so the tag is a single decision rather
  than an hour of work.
- **No customer-facing emergency in this tranche.** 2.7.5 fixed what the
  customer was blocked on and they confirmed it. This is correctness and
  diagnosability, so it can wait for a deliberate cut.

## Open

- `main` will declare `2.7.6` while accumulating post-release commits again.
  That is the accepted cost of not opening a `.devN`; the next release bumps the
  surfaces as its first act.
